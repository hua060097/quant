## 修改前的架构（有问题）

### 架构图

```
主线程：for循环遍历持仓
  ├─ 持仓A
  │   ├─ 启动监控线程（后台）✅
  │   └─ while循环：显示摘要（主线程阻塞）❌
  │       └─ 只有等A监控结束，才会处理B
  ├─ 持仓B
  │   └─ （等待A结束...）
  └─ 持仓C
      └─ （等待B结束...）
```

### 问题

1. **主线程阻塞**：`while monitor_5m.is_monitoring` 阻塞主线程
2. **无法同时监控多个持仓**：必须等A监控结束，才能启动B
3. **用户体验差**：看起来程序卡住了

**代码示例**（main.py 旧代码）：
```python
# 启动监控
monitor_5m.start_5m_monitoring()

# ❌ 主线程阻塞在这里，等待监控结束
while monitor_5m.is_monitoring:
    positions_summary = monitor_5m.get_positions_summary()
    # 显示摘要
    time.sleep(60)

# 只有监控结束后，才会继续处理下一个持仓
continue
```

## 修改后的架构（优化）

### 架构图

```
主线程：for循环遍历持仓（不阻塞）
  ├─ 持仓A
  │   └─ 启动监控线程（后台，包含监控+摘要）✅
  ├─ 持仓B
  │   └─ 启动监控线程（后台，包含监控+摘要）✅
  └─ 持仓C
      └─ 启动监控线程（后台，包含监控+摘要）✅
  → 主线程继续执行（不阻塞）
```

### 优点

1. ✅ **主线程不阻塞**：启动监控后立即继续
2. ✅ **可以同时监控多个持仓**：A、B、C同时运行
3. ✅ **更好的用户体验**：程序响应快
4. ✅ **代码更简洁**：删除了大量重复的显示摘要代码

**代码示例**（main.py 新代码）：
```python
# 启动监控
monitor_5m.start_5m_monitoring()

# ✅ 主线程不阻塞，继续处理下一个持仓
continue
```

### 3. 添加打印摘要的方法

**新增方法**：`_print_positions_summary()` (第768-810行)

```python
def _print_positions_summary(self):
    """
    打印持仓摘要（在监控循环中每5分钟调用一次）

    不返回数据，直接打印到日志
    """
    if not self.positions:
        return

    try:
        self.logger.info("=" * 60)
        self.logger.info("📊 持仓摘要")
        self.logger.info("=" * 60)

        for stock_code, position in self.positions.items():
            # 获取当前价格
            current_price = self.trader.get_current_price(stock_code)

            # 计算收益率
            profit_pct = (current_price - position['entry_price']) / position['entry_price'] * 100

            # 计算持仓天数
            days_held = (datetime.now().date() - position['entry_date']).days

            # 打印摘要
            self.logger.info(f"股票: {stock_code}")
            self.logger.info(f"  买入价: {position['entry_price']:.2f}")
            self.logger.info(f"  当前价: {current_price:.2f}")
            self.logger.info(f"  收益率: {profit_pct:+.2f}%")
            self.logger.info(f"  持仓天数: {days_held}天")
            self.logger.info(f"  最大回撤: {position['max_decline_from_entry']:.2%}")
            self.logger.info(f"  连续阴线: {position['consecutive_bearish']}根")
            self.logger.info("-" * 60)

    except Exception as e:
        self.logger.error(f"打印持仓摘要失败: {e}")
```

**特点**：
- ✅ 在监控线程中调用，不阻塞主线程
- ✅ 每5分钟自动打印（与收集K线数据同步）
- ✅ 直接输出到日志，无需返回数据
- ✅ 简洁清晰，约30行代码

| 监控线程 | 1 | 只有当前正在监控的持仓 |
| **总计** | **2个线程** | 但同时只有1个持仓在监控 |

### 修改后

**场景**：3个持仓（A、B、C）

| 线程 | 数量 | 说明 |
|------|------|------|
| 主线程 | 1 | 不阻塞，快速启动后退出 |

| **总计** | **4个线程** | 3个持仓同时监控 |

- 监控线程是 `daemon=True`（后台线程）

## 常见问题

### Q1: 如果用户想同时监控3个持仓，现在会怎样？
**A**:
- **修改前**：只能监控1个，必须等第1个结束，才能启动第2个
- **修改后**：同时启动3个监控线程，互不影响

### Q2: 持仓摘要多久打印一次？
**A**: 每5分钟打印一次（与收集5分钟K线数据同步）

### Q3: 午间休市时还打印摘要吗？
**A**: 不打印。因为午间休市时，`_collect_5min_kline_data()` 会智能休眠，不会调用 `_print_positions_summary()`

### Q4: 如果持仓很多（如10个），会有10个线程吗？
**A**: 是的，会有10个监控线程。但因为它们大部分时间都在sleep（每5分钟才醒来一次），实际资源占用很小。

### Q5: 主线程启动完所有监控后去哪了？
**A**: 主线程会退出 `for` 循环，然后根据程序逻辑继续执行或退出。监控线程（daemon=True）会继续在后台运行。
