## 问题描述

### 用户提问
> "中午休盘时五分钟监控和摘要输出有停止或者做什么减小电脑运行压力的操作吗，请分析现在的午间休市时的处理是否合理"

### 问题分析

午间休市时间：**11:30 - 13:00**（共90分钟）

**原始处理逻辑**：

1. **监控循环** (monitor.py):
   ```python
   if not self._is_trading_time():
       time.sleep(60)  # ❌ 每60秒检查一次
       continue
   ```
   - 午间休市期间：每60秒检查一次 `is_trading_time()`
   - 总计：90次循环

2. **显示摘要循环** (main.py):
   ```python
   while monitor_5m.is_monitoring:
       positions_summary = monitor_5m.get_positions_summary()
       # 显示摘要
       time.sleep(60)  # ❌ 每60秒刷新一次
   ```
   - 午间休市期间：每60秒刷新一次持仓摘要
   - 总计：90次刷新 + 90条日志输出

### 性能问题

**午间休市90分钟期间**：
- ❌ **监控循环**：90次循环（每60秒检查一次）
- ❌ **显示摘要循环**：90次刷新（每60秒刷新一次）
- ❌ **总计**：**180次循环** + **90条日志输出**
- ❌ **资源浪费**：频繁唤醒CPU、持续输出日志、占用内存

## 优化方案

### 核心思路

**智能休市处理**：
1. **监控循环**：检测到午间休市时，一次性sleep整个休市时间（90分钟）
2. **显示摘要循环**：午间休市时不显示摘要，减少刷新频率
3. **提前休眠**：在11:25-11:30期间，提前进入休市模式

#### 1. 新增智能休市处理方法

**文件**: `live_trading/monitor.py`

**新增方法**: `_sleep_through_lunch_break()` (第694-743行)

```python
def _sleep_through_lunch_break(self):
    """
    智能午间休市处理：一次性sleep整个午间休市时间

    午间休市时间：11:30 - 13:00（90分钟）

    优化效果：
    - 避免每60秒检查一次（原方案需90次循环）
    - 一次性sleep整个休市时间（只需1次sleep）
    - 减少CPU唤醒次数和日志输出
    """
    now = datetime.now()
    current_time = now.strftime('%H:%M:%S')

    # 午间休市：11:30 - 13:00
    lunch_start = "11:30:00"
    lunch_end = "13:00:00"

    # 判断是否在午间休市时间
    if lunch_start <= current_time < lunch_end:
        # 计算距离13:00还有多少秒
        lunch_end_datetime = now.replace(hour=13, minute=0, second=0, microsecond=0)
        wait_seconds = (lunch_end_datetime - now).total_seconds()

        # 额外加30秒缓冲，确保13:00已经开市
        wait_seconds += 30

        if wait_seconds > 0:
            self.logger.info("=" * 60)
            self.logger.info(f"🍽️  午间休市（11:30-13:00）")
            self.logger.info(f"💤 系统将休眠 {int(wait_seconds // 60)}分钟 {int(wait_seconds % 60)}秒")
            self.logger.info(f"⏰ 预计唤醒时间: 13:00:30")
            self.logger.info("=" * 60)

            # 一次性sleep整个午间休市时间
            time.sleep(wait_seconds)

            self.logger.info("=" * 60)
            self.logger.info("☕️ 午间休市结束，恢复监控")
            self.logger.info("=" * 60)

    elif current_time < lunch_start:
        # 在早盘，但接近午间休市（11:25-11:30）
        if current_time >= "11:25:00":
            # 计算距离11:30还有多少秒
            lunch_start_datetime = now.replace(hour=11, minute=30, second=0, microsecond=0)
            wait_seconds = (lunch_start_datetime - now).total_seconds()

            if wait_seconds > 0 and wait_seconds < 300:  # 5分钟内
                self.logger.info(f"⏰ 距离午间休市还有 {int(wait_seconds)}秒，提前休眠")
                time.sleep(wait_seconds)
```

**关键特性**：
- ✅ **一次性休眠**：计算剩余休市时间，一次性sleep
- ✅ **提前进入休市**：11:25后检测到接近休市，提前休眠
- ✅ **缓冲时间**：加30秒缓冲，确保13:00已开市
- ✅ **详细日志**：显示休眠时长和预计唤醒时间

## 常见问题

### Q1: 为什么午间休市时显示摘要循环还需要5分钟刷新一次？
**A**: 虽然午间休市时不显示摘要，但循环本身还需要检查 `is_monitoring` 状态，以便在监控停止时能够退出。5分钟刷新一次已经足够，无需60秒。

### Q2: 如果用户想在11:30-13:00期间手动停止怎么办？
**A**: 按 `Ctrl+C` 可以随时中断sleep，停止监控。

### Q3: 为什么加30秒缓冲？
**A**:
1. **确保13:00已开市**：避免13:00:00时刚好在sleep中，错过13:00的第一根K线
2. **时间精度**：系统sleep可能有微小误差，30秒缓冲确保安全
3. **实际影响**：13:00:30恢复监控，只晚30秒，影响可忽略

### Q4: 提前休眠（11:25-11:30）会不会错过11:30的K线？
**A**: 不会。因为：
1. **11:25-11:30只是接近休市**，还没到11:30
2. **11:30的K线在13:00才生成**（收盘后才有完整数据）
3. **提前休眠只是sleep到11:30**，不会影响11:30的K线收集
