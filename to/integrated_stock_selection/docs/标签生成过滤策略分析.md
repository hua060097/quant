# 标签生成过滤策略分析报告

## 概述

本报告分析了 `_generate_training_labels_for_all_data` 函数中 `process_board_labels` 子函数的数据过滤策略，特别是涨跌停和异常数据的处理方式。

## 过滤策略分析

### 1. 数据过滤逻辑

`process_board_labels` 函数在第6892-6933行实现了以下过滤策略：

#### 1.1 基础有效性过滤
```python
# 第6896行
valid_mask = board_data['weighted_return'].notna()
```
- 过滤掉 `weighted_return` 为 NaN 的数据

#### 1.2 涨跌停过滤
```python
# 过滤涨停（第6899-6902行）
if 'is_limit_up' in board_data.columns:
    limit_up_count = (board_data['is_limit_up'] == 1).sum()
    valid_mask &= (board_data['is_limit_up'] != 1)

# 过滤跌停（第6916-6919行）
if 'is_limit_down' in board_data.columns:
    limit_down_count = (board_data['is_limit_down'] == 1).sum()
    valid_mask &= (board_data['is_limit_down'] != 1)
```

#### 1.3 异常涨幅过滤
```python
# 主板异常涨幅过滤（第6906-6909行）
if board_name == "主板":
    weighted_error_count = (board_data['weighted_return'] > 0.22).sum()
    valid_mask &= (board_data['weighted_return'] <= 0.32)

# 创业板异常涨幅过滤（第6910-6913行）
else:
    weighted_error_count = (board_data['weighted_return'] > 0.62).sum()
    valid_mask &= (board_data['weighted_return'] <= 0.62)
```

#### 1.4 流动性过滤
```python
# 第6922-6925行
if 'amount' in board_data.columns:
    low_liquidity_count = (board_data['amount'] < 10_000_000).sum()
    valid_mask &= (board_data['amount'] >= 10_000_000)
```

### 2. 被过滤数据的标签处理

**关键发现**：被过滤的数据标签设置为 NaN！

#### 2.1 标签赋值逻辑
```python
# 第7153-7155行
board_data.loc[valid_mask, 'atr_return_label'] = (
    board_data.loc[valid_mask, 'weighted_return']
)
```

**问题所在**：
- 只有通过 `valid_mask` 的数据（即未被过滤的数据）才会被赋予标签
- 被过滤的数据（`~valid_mask`）的 `atr_return_label` 列保持为 NaN 或未定义状态

#### 2.2 特殊情况处理
```python
# 第6930-6933行
if valid_count == 0:
    logger.warning(f"  ⚠️ {board_name} 没有有效样本")
    board_data['atr_return_label'] = np.nan
    return board_data
```

### 3. 过滤策略的量化交易评估

#### 3.1 优点 ✅

1. **涨跌停过滤**：合理
   - 涨跌停的股票无法正常交易，价格失真
   - 涨停股票次日大概率低开，跌停股票次日大概率高开
   - 过滤掉这些数据避免模型学习到异常的价格模式

2. **流动性过滤**：合理
   - 成交额低于1000万的股票流动性差
   - 大资金难以进出，滑点成本高
   - 过滤掉这些股票符合实际交易需求

3. **异常涨幅过滤**：合理但阈值可讨论
   - 主板过滤>32%的涨幅，创业板过滤>62%的涨幅
   - 避免极端数据影响模型训练
   - 但可能过滤掉一些真正的牛股

#### 3.2 缺点和问题 ❌

1. **标签处理方式不当**：
   - 被过滤的数据标签为 NaN，而不是明确的特殊值
   - 在后续的模型训练中，这些样本会被跳过
   - **问题**：浪费了这些数据，模型无法从这些情况中学习

2. **信息丢失**：
   - 模型无法学习到"涨停股次日表现"这种模式
   - 无法学习到"低流动性股票的风险特征"
   - 这些信息在实际交易中是有价值的

3. **过滤时机问题**：
   - 在标签生成阶段过滤，而不是在特征工程阶段
   - 导致特征和标签的一致性问题

### 4. 最佳实践建议

#### 4.1 改进方案 1：使用特殊标签值
```python
# 建议的改进方案
# 为被过滤的数据分配特殊标签，而不是NaN

if 'is_limit_up' in board_data.columns:
    # 涨停股标签为特殊值，如 -1 或其他预定值
    board_data.loc[board_data['is_limit_up'] == 1, 'atr_return_label'] = -1.0

if 'is_limit_down' in board_data.columns:
    # 跌停股标签为特殊值
    board_data.loc[board_data['is_limit_down'] == 1, 'atr_return_label'] = -2.0

if 'amount' in board_data.columns:
    # 流动性不足标签为特殊值
    board_data.loc[board_data['amount'] < 10_000_000, 'atr_return_label'] = -3.0
```

#### 4.2 改进方案 2：在特征层面处理
```python
# 在特征工程阶段添加过滤标识
board_data['is_filtered'] = False
board_data.loc[board_data['is_limit_up'] == 1, 'is_filtered'] = True
board_data.loc[board_data['amount'] < 10_000_000, 'is_filtered'] = True

# 保留所有数据的标签，但在模型中处理过滤标识
board_data['atr_return_label'] = board_data['weighted_return']
```

#### 4.3 改进方案 3：分层建模
1. **正常数据**：使用标准标签
2. **异常数据**：
   - 单独建模预测涨停概率
   - 或使用多任务学习框架

### 5. 对模型性能的影响

#### 5.1 当前方案的影响
- **训练数据减少**：过滤掉了相当比例的数据
- **偏差增加**：模型只"看到"正常交易情况
- **泛化能力受限**：无法处理异常情况

#### 5.2 量化交易视角
1. **现实需求**：
   - 需要识别可能涨停的股票（避免追高）
   - 需要识别流动性风险
   - 需要应对异常波动

2. **建议**：
   - 保留所有数据，使用适当的方式标记异常情况
   - 让模型学习这些特征和未来收益的关系
   - 在策略执行时再决定是否过滤

## 结论

当前的过滤策略在逻辑上是合理的（过滤了确实难以交易的股票），但在实现方式上存在改进空间：

1. **标签设置为 NaN 是不合适的**，浪费了有价值的信息
2. **应该在特征层面处理过滤标识**，而不是丢弃数据
3. **保留异常数据**，让模型学习这些情况下的收益模式

改进后的方案将使模型更加鲁棒，能够更好地应对真实交易环境中的各种情况。
