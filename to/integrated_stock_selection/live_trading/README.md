# 实盘交易系统使用说明（智能状态机版本）

## 系统概述

本系统基于训练好的量化模型，实现A股实盘自动交易。采用**状态机架构**，根据账户持仓状态智能选择执行路径。

### 支持模式

1. **选股模式**: T日收盘后运行，基于模型预测选出top N只股票（默认top 3）
2. **交易模式**: T+1日及之后运行，根据持仓状态智能执行：
   - **有持仓第2天** (holding_days=1) → 启动5分钟风控监控（无尾盘卖出）
   - **有持仓第3天** (holding_days=2) → 启动5分钟风控监控（14:55尾盘卖出）
   - **有持仓第1天** (holding_days=0) → 提示无需监控，退出
   - **无持仓+买入日** → 全仓买入top1股票
   - **无持仓+非买入日** → 退出
3. **手动模式**: 随时运行，手动控制买入或卖出：
   - **手动买入** → 指定金额，立即执行
   - **手动卖出** → 指定手数或全仓卖出
   - **跳过风控** → 无需等待开盘，无跳空检查

### 核心特性

#### 交易功能
- ✅ **只买入top1股票**: 集中资金买入最优质的股票
- ✅ **全仓买入**: 不留缓冲，资金利用率最大化
- ✅ **智能状态识别**: 自动识别持仓天数并执行对应操作
- ✅ **持仓天数计算**: 基于交易日历精确计算持仓天数
- ✅ **交易记录增强**: 完整记录买入日期、价格、数量、卖出原因

#### 订单管理
- ✅ **智能订单管理**: 完整的订单生命周期管理（下单、监控、撤单、重试）
- ✅ **开盘风控**: 09:30开盘后立即进行跳空检查
- ✅ **回调机制**: 实时接收订单状态、成交回报、订单错误
- ✅ **自动重试**: 部成、超时、废单自动撤单重试（最多3次）
- ✅ **精确重试间隔**: 每次重试间隔5秒

#### 风控监控
- ✅ **5分钟K线监控**: 实时监控持仓风险
- ✅ **累计下跌风控**: 累计下跌 > 5%（相对买入价）→ 立即卖出
- ✅ **连续阴线风控**: 连续3根5分钟阴线 → 立即卖出
- ✅ **14:55尾盘卖出**: 持仓第3天（holding_days=2）14:55自动卖出
- ✅ **T+2生效**: 从买入后第2个交易日开始执行风控

## 环境准备

### 1. 安装迅投API

```bash
pip install xtquant
```

### 2. 配置迅投客户端

1. 下载并安装迅投MiniQMT客户端
2. 登录客户端并保持运行
3. 记录`userdata_mini`路径和资金账号

### 3. 修改配置文件

编辑 `live_trading/config.py`:

```python
class XtQuantConfig:
    # MiniQMT客户端路径（必填）
    USERDATA_MINI_PATH = "D:\\迅投极速交易终端\\userdata_mini"

    # 资金账号（必填）
    ACCOUNT_ID = "1000000365"

    # 会话ID基础值（系统会自动添加时间偏移确保唯一性）
    SESSION_ID_BASE = 123456
```

**注意事项**：
- ⚠️ MiniQMT客户端必须保持运行
- ⚠️ Python API不需要密码（客户端已登录）
- ⚠️ 路径必须指向`userdata_mini`目录
- ✅ **session_id自动生成**：系统会在基础ID上自动添加时间偏移，确保多实例运行时不冲突。例如：基础ID 123456 + 偏移 112 = 实际session_id 123568。无需手动修改。


**状态机逻辑**：

```

                              ↓
              ┌───────────────┼───────────────┐
              ↓               ↓               ↓
         [无持仓]       [有持仓第1天]    [有持仓第2天+]
              ↓               ↓               ↓
         今天是买入日？   提示无需监控    计算持仓天数
              ↓          退出程序         ↓
          [是]   [否]                    [holding_days=1/2/?]
           ↓      ↓                         ↓     ↓      ↓
        买入    退出                    第2天  第3天  >=3天
                                         ↓      ↓      ↓
                                      监控   监控    卖出
                                      (无尾盘) (14:55) (异常)
```

### 模式3: 手动交易模式

**适用场景**：需要手动控制买入或卖出操作时使用

**特点**：
- ✅ **即时执行**：无需等待开盘或风控检查，立即下单
- ✅ **灵活控制**：可指定买入金额或卖出数量
- ✅ **智能计算**：自动根据实时价格计算可买手数
- ✅ **资金验证**：确保用户金额不超过可用资金
- ✅ **重试机制**：复用trade模式的订单重试逻辑
- ✅ **完整记录**：所有交易保存到trade_records.json

#### 3.1 手动买入

**命令格式**：
```bash
python live_trading\main.py --mode manual --operation buy --stock <股票代码> --amount <最大金额>
```

**参数说明**：
- `--mode manual`: 手动模式
- `--operation buy`: 买入操作
- `--stock`: 股票代码（如 600000.SH）
- `--amount`: 最大买入金额（元）

**示例**：
```bash
# 买入600506.SH，最大金额3000元
python live_trading\main.py --mode manual --operation buy --stock 600506.SH --amount 3000
```

**执行逻辑**：
1. 连接迅投API
2. 查询账户可用资金
3. 获取股票当前价格
4. 计算可买手数：
   ```
   max_lots_by_cash = int(可用资金 / (当前价 × 100))
   planned_lots = int(用户金额 / (当前价 × 100))
   buy_lots = min(max_lots_by_cash, planned_lots)
   ```
5. 执行买入（重试最多3次）
6. 保存交易记录

## 智能订单管理详解

### 订单重试机制

#### 重试次数
- **最多重试3次**: `MAX_RETRY_TIMES = 3`
- 可在`order_manager.py`中修改

#### 重试间隔
- **每次重试间隔5秒**: `RETRY_INTERVAL = 5`
- 撤单后等待5秒再重新下单

#### 重试触发条件

| 条件 | 处理方式 |
|------|---------|
| **部分成交**（状态52） | 检查成交量，如果为0则撤单重试 |

| **废单**（状态57） | 调整参数后重试 |
| **已撤**（状态54） | 立即重新下单 |
| **部撤**（状态55） | 重新下单剩余部分 |

#### 订单超时时间
- **订单超时**: 30秒未成交视为超时
- 可在`order_manager.py`中修改：`ORDER_TIMEOUT = 30`

### 订单状态码详解

## 5分钟风控监控详解

### 监控启动时机

- ✅ **持仓第2天**（holding_days = 1）
- ✅ **持仓第3天**（holding_days = 2）
- ❌ **持仓第1天**（holding_days = 0，当天无法卖出）
- ❌ **持仓满3天**（holding_days >= 3，立即卖出）

### 风控规则

#### 规则1：累计下跌风控

**触发条件**：
```
累计下跌 > 5%（相对买入价）
即：(当前价 - 买入价) / 买入价 < -0.05
```

**示例**：
```
买入价: 10.50元
当前价: 9.97元
累计下跌: (9.97 - 10.50) / 10.50 = -5.05%
触发: ✅ 立即卖出
```

#### 规则2：连续阴线风控

**触发条件**：
```
连续3根5分钟K线都是阴线
即: Close < Open 连续出现3次
```

**示例**：
```
09:35 K线: Close=10.48 < Open=10.50 → 阴线1
09:40 K线: Close=10.45 < Open=10.48 → 阴线2
09:45 K线: Close=10.42 < Open=10.45 → 阴线3
触发: ✅ 立即卖出
```

#### 规则3：14:55尾盘卖出

**触发条件**：
```
持仓天数 = 2（持仓第3天）
当前时间 >= 14:55
```

**示例**：
```
买入日: 2025-01-10（交易日历索引=100）
今天:   2025-01-14（交易日历索引=102）
持仓天数: 102 - 100 = 2天
触发: 14:55时自动卖出
```

**说明**：
- 只有持仓第3天（holding_days=2）才会在14:55尾盘卖出
- 第2天（holding_days=1）不会执行尾盘卖出
- 如果在14:55前已触发风控（规则1或规则2），则不会执行尾盘卖出

#### 规则4：持仓异常处理

**触发条件**：
```
持仓天数 >= 3（异常情况）
```

**示例**：
```
买入日: 2025-01-10（交易日历索引=100）
今天:   2025-01-15（交易日历索引=103）
持仓天数: 103 - 100 = 3天
触发: ⚠️ 立即卖出（异常情况）
```

**说明**：
- 持仓天数 >= 3 是异常情况，理论上不应该出现
- 正常情况下第3天14:55就已经卖出
- 如果出现此情况，立即卖出以控制风险

### T+2生效机制

**为什么需要T+2？**

A股T+1制度：
- **T日（买入日）**: 当天买入的股票无法当天卖出
- **T+1日（第2天）**: 可以卖出，但5分钟监控从这天开始才生效

**实现**：
```python
def _is_after_t2(self, entry_date: datetime.date) -> bool:
    """判断当前是否已到T+2（买入日的下一个交易日）"""
    entry_index = self.trading_dates.index(entry_date)
    t2_index = entry_index + 1  # T+2的索引
    today_index = self.trading_dates.index(today)

    return today_index >= t2_index
```

**示例**：
```
买入日: 2025-01-10（索引100）
T+2日: 2025-01-13（索引101）

如果今天是2025-01-10（索引100）:
  today_index (100) >= t2_index (101)? 否 → 不执行风控

如果今天是2025-01-13（索引101）:
  today_index (101) >= t2_index (101)? 是 → 开始执行风控
```

```python
def _sleep_to_next_5min(self):
    """休眠到下一个5分钟整数倍"""
    now = datetime.now()
    minute = now.minute
    next_minute = ((minute // 5) + 1) * 5

    if next_minute >= 60:
        next_time = now.replace(hour=now.hour + 1, minute=0, second=0)
    else:
        next_time = now.replace(minute=next_minute, second=0)

    wait_seconds = (next_time - now).total_seconds()
    time.sleep(wait_seconds)
```

## 持仓天数计算详解

### 计算原理

**使用交易日历**（而非自然日）：

```python
holding_days = today_index - entry_index
```

**示例**：
```
交易日历: [2025-01-08, 2025-01-09, 2025-01-10, 2025-01-13, 2025-01-14, ...]
索引:        [0,          1,          2,          3,          4,        ...]

买入日: 2025-01-10（索引2）
今天:   2025-01-13（索引3）

持仓天数 = 3 - 2 = 1天
```

### 为什么使用交易日历？

**自然日计算的问题**：
```
买入日: 2025-01-10（周五）
自然日: 2025-01-11（周六）→ 持仓1天 ❌ 周末不交易
自然日: 2025-01-12（周日）→ 持仓2天 ❌ 周末不交易
自然日: 2025-01-13（周一）→ 持仓3天 ✓ 实际只过1个交易日
```

**交易日历计算**：
```
买入日: 2025-01-10（周五，索引2）
交易日: 2025-01-13（周一，索引3）
持仓天数 = 3 - 2 = 1天 ✓ 正确
```

### 容错机制

如果日期不在交易日历中：
```python
# 使用自然日计算
holding_days = (today - entry_date).days
```

## 过滤规则

### 选股阶段过滤

系统会自动过滤以下股票：

1. **ST股票**: 股票代码包含"ST"
2. **涨停股**: `is_limit_up == 1`
3. **跌停股**: `is_limit_down == 1`
4. **新股**: 上市不足30天
5. **流动性不足**: `amount < 1000万`

### 交易阶段风控

**开盘风控**（在买入时执行）：
- 使用`get_full_tick()`获取真实开盘价（盘中实时数据）
- 跌空 > 3% → 跳过买入
- 高开 > 5% → 跳过买入

**开盘价获取机制**：
- **买入当日（9:35启动）**：通过`get_full_tick()`获取全推实时快照数据，提取`open`字段作为开盘价
- **第2、3天监控**：通过`subscribe_quote`订阅的实时行情数据获取最新价
- 两种方式都能在盘中准确获取开盘价，不依赖`get_market_data_ex`（该接口需要预先下载历史数据）

**盘中风控**（在监控时执行）：
- 累计下跌 > 5% → 立即卖出
- 连续3根阴线 → 立即卖出
- 持仓满3天 → 立即卖出

## 常见问题

### Q1: 为什么只买入top1股票?
A: 集中资金买入最优质的股票，提高资金利用率，简化管理。

### Q2: 什么是全仓买入?
A: 使用账户全部可用资金买入，不留缓冲（5%）。剩余资金保留在账户。

### Q3: 如何计算持仓天数?
A: 使用交易日历计算：`holding_days = today_index - entry_index`。这确保只有交易日才计入持仓天数。

### Q4: 为什么买入当天无法监控?
A: A股T+1制度，当天买入的股票当天无法卖出（持仓天数=0），所以无需监控。

### Q5: 订单重试几次? 间隔多久?
A: 最多重试3次，每次重试间隔5秒。可在`order_manager.py`中修改：
```python
MAX_RETRY_TIMES = 3      # 最多重试次数
RETRY_INTERVAL = 5       # 重试间隔（秒）
ORDER_TIMEOUT = 30       # 订单超时（秒）
```

### Q6: 如何修改风控参数?
A: 编辑`monitor.py`中的`_check_position_risk_5m()`方法：
```python
# 修改累计下跌阈值（默认5%）
if decline_from_entry < -0.05:  # 改为其他值

# 修改连续阴线阈值（默认3根）
if position['consecutive_bearish'] >= 3:  # 改为其他值

# 修改最大持仓期（默认3天）
return trading_days_held >= 3  # 改为其他值
```

### Q7: 如何查看订单状态?
A: 查看日志文件，系统会打印订单回调信息：
```
[订单回调] 600000.SH 订单12345 状态: 50
[订单回调] 600000.SH 订单12345 状态: 52
[订单回调] 600000.SH 订单12345 状态: 53
✅ 订单全部成交: 12345
```

### Q8: 交易记录包含哪些信息?
A: 买入记录包含：股票代码、买入日期、买入价格、买入数量、订单号、时间戳
   卖出记录包含：股票代码、卖出日期、卖出价格、收益率、退出原因、订单号、时间戳

### Q9: 为什么移除了--num_stocks和--total_amount参数?
A:
- `--num_stocks`: 只买top1，不需要指定数量
- `--total_amount`: 全仓买入，自动查询账户资金

### Q10: 如何停止监控?
A: 按`Ctrl+C`停止监控。系统会保存持仓信息，下次运行会正确识别持仓状态。

### Q11: 可以手动干预卖出吗?
A: 可以。你可以随时通过迅投客户端手动卖出。下次运行程序时，如果账户无持仓，会自动进入买入流程。

### Q12: 系统会自动启动监控吗?
A: 不会。每次启动程序后：
- 如果有持仓第2天+ → 进入监控模式
- 如果无持仓 → 买入后退出
- 需要每天运行程序来维持监控

### Q13: 如何查看历史交易记录?
A: 查看`live_trading/trade_records.json`文件，或查看日志文件。

### Q14: 如果程序崩溃怎么办?
A: 持仓信息保存在`trade_records.json`中，下次运行会正确恢复持仓状态。

### Q15: 手动模式和Trade模式有什么区别?
A: 主要区别如下：
- **买入时机**：Manual立即执行，Trade需等09:30开盘
- **风控检查**：Manual跳过风控，Trade有跳空检查
- **买入金额**：Manual用户指定，Trade全仓买入
- **状态管理**：Manual无状态管理，Trade自动识别持仓状态
- **监控启动**：Manual不启动监控，Trade自动启动5分钟监控

### Q16: 什么时候应该使用手动模式?
A: 建议在以下场景使用手动模式：
- **紧急止损**：需要立即卖出，无法等待开盘
- **测试验证**：小金额测试订单执行流程
- **手动调仓**：需要精确控制买入金额或卖出数量
- **非交易时间**：需要在非开盘时段执行交易

### Q17: 手动买入会重复下单吗?
A: 不会。修复后的代码正确识别订单状态56（已成交），不会触发错误的重试。每次手动买入只会下单1次。

### Q18: 手动模式会启动5分钟监控吗?
A: 不会。手动模式执行一次后立即退出，不会启动任何监控。如需监控，请使用Trade模式。

### Q19: 手动模式的交易记录如何保存?
A: 手动交易记录保存在`trade_records.json`中，action字段为`manual_buy`或`manual_sell`，与Trade模式的记录区分开。

### Q20: 系统如何获取开盘价？
A: 系统区分两种场景：
- **买入当日（9:35启动）**：使用`xtdata.get_full_tick()`获取全推实时快照数据，提取`open`字段作为真实开盘价
- **第2、3天监控**：使用`subscribe_quote`订阅的实时行情数据（通过`trader.get_current_price()`获取）

两种方式都能在盘中准确获取开盘价，不依赖`get_market_data_ex`（该接口需要预先下载历史数据，盘中无法获取当日数据）。

### Q21: 为什么不使用get_market_data_ex获取开盘价？
A: 因为`get_market_data_ex`在非订阅模式下需要先通过`download_history_data`下载数据到本地，但`download_history_data`只能在盘后下载历史数据（当日数据还未收盘，不属于历史数据），所以盘中无法获取当日开盘价。因此系统改用`get_full_tick()`获取实时快照数据。

## 注意事项

### 重要提醒

1. **交易日历依赖**: 首次运行需要联网加载交易日历（使用迅投API）
2. **交易记录重要性**: 不要手动删除或修改`trade_records.json`
3. **T+1制度**: 买入当天无法卖出（持仓天数=0）
4. **迅投客户端**: 交易时必须保持迅投客户端运行
5. **资金安全**: 建议先用小资金测试
6. **订单监控**: 系统会通过回调实时监控订单状态
7. **重试机制**: 部成、超时、废单会自动撤单重试（最多3次）
8. **手动停止**: 可以按Ctrl+C停止监控，持仓信息会保存

### 系统限制

1. **单持仓**: 系统设计为只持有1只股票
2. **全仓买入**: 不留资金缓冲
3. **持仓期限**: 最长持仓3个交易日
4. **风控触发**: 风控触发后立即卖出，不会等待
5. **手动干预**: 可以随时通过迅投客户端手动买卖

### 最佳实践

1. **每日运行**: 每天运行一次程序，确保持仓得到监控
2. **监控时间**: 建议在09:30开盘后运行
3. **日志查看**: 定期查看日志文件，了解系统运行状态
4. **记录备份**: 定期备份`trade_records.json`
5. **参数调整**: 根据市场情况调整风控参数
