# 因子搜索总体架构 V3 提案

> **日期**：2026-10-14<br>
> **状态**：研究方案提案，尚未授权代码实现；不替代或修改 `TECHNICAL.md`、`MERGE_V2_PLAN.md` 中已冻结的规则。<br>
> **目标**：遵循 PLAN D8，把 `pandaai_online/merge` 建成一套面向**本地 VWAP 口径下的纯个股因子与交互因子**的顶级、可复现搜索/评估/筛选引擎：覆盖多候选来源与机制、可靠拒绝无效候选、校准筛选误差、控制搜索预算，并让结论可追溯。C2C 因子大赛适配是可选扩展；它的字段/上传限制只在大赛导出和运行边界生效，不能限制 merge 的本地搜索能力。
>
> **文档落位约束**：本文件是应用户本轮要求新建的一次性评审提案，不是第二套长期权威规格。若用户批准其中决策，应把批准的规范写入 `docs/MERGE_V2_PLAN.md`、实现接口与事实写入 `TECHNICAL.md`，随后在本提案顶部标明已 superseded 并指向正式落点；不在两处平行维护同一规则（TECHNICAL §0.6）。

## 一页结论

1. **不推翻整套门控工程。** 保留门控台账、数据边界、G0–G3/G4 诊断、F1 计算、族校验和生产模型外部对照接口；把当前 54 个固定规格重新定位为 **Gate Grid V1 基准候选库**，而不是“门控可能性的完整搜索器”。
2. **修正 0/720 的含义。** 当前 F1v2 的 720 是 **36 个市场门控 × 20 个 `base20` 因子 × `s=+1`**；它不是 54 个市场/行业门控与全部个股因子的联合测试。门控组级 G2/G3 使用的是 `ic124`（124 个 `role=STOCK` 因子的 IC 矩阵），但 F1 条件增量只测了选定的 20 个因子。F1v2 清单不含 14 个行业门控。故 **FDR 0/720 仅表示当前已登记的这组市场交互检验没有成员通过该族校正**，不能推出“所有门控都没用”或“门控架构失败”。
3. **用户的候选集质疑成立。** `base20` 是一个经过筛选的参考面板，不自动代表全部个股特征、当前生产模型的真实输入，或各经济机制的均衡样本。它适合保留为历史比较/探索面板，不应继续作为判断所有门控价值的唯一正式入口。
4. **研究任务不再二分为“个股因子 / 门控因子”。** 改用“数据粒度 × 经济角色 × 使用任务 × 计算/部署能力”的多维分类。Beta、市场状态、行业扩散、横截面 Alpha、流动性与可交易性不应被塞进两个互斥桶。
5. **当前主线是本地 VWAP 搜索引擎。** Phase 0 审计候选生成、表达能力、评估/筛选正确性、预算、数据边界和可复现性；720 结果的零成本归因作为一个历史诊断。Stage15 的因子池/数据切分是一轮特定实验，可由用户在后续单独优化，不定义 merge 的固定搜索空间或验收目标。
6. **C2C 是适配器，不是搜索边界。** 本地 VWAP profile 默认优先；本地可计算的行业/市场上下文和 local-only 算子允许进入搜索、评估和短名单。C2C profile/`export`/`upload` 仅过滤平台不可表达的候选；过滤结果不得反向删除本地候选或缩小后续本地搜索。仍遵循 D8，不启动 standalone 行业轮动研究。

### 对此前表述的明确修正

“当前 54 规格 × 20 因子在正式口径下没有合格候选”不够准确，应改为：

> **当前 F1v2 市场交互族（36 个市场规格 × 20 个已选参考因子，s=+1）在斜率尺下 h3=20/720、联合 FDR=0/720。** 这是这一个族、这一个面板、这条统计口径的结果。G2/G3 另使用 124 个 STOCK 因子的日 IC 作组级统计；行业交互不在 F1v2 720 中。

因此，0/720 是一个重要的**局部否定结果**：当前登记的市场门控与 `base20` 交互没有通过族校正。它要求我们审视条件增量的候选面板和检验独立性，不是推翻搜索器、G2/G3、或所有市场/行业状态变量的证据。

## 2. 对 Kimi / Codex 方案的综合判断

| 提议 | 判断与改进 |
|---|---|
| 特征统一注册、记录血缘与角色 | 方向正确。先把 `field_catalog.py`、`roles.csv`、`base20.json`、门控规格、生产模型输入清单映射成一份**可审计的元数据契约**；不要未核对职责前就再造一套互相冲突的 `feature_registry.py`、`role_annotation.py`。注册表能管理已有特征，不能创造算子或搜索能力。 |
| 门控自身预测（A）与条件增量（B）分开 | 采纳。A 回答状态变量是否预测市场/行业收益或风险；B 回答它能否调制横截面 Alpha。A 可帮助揭示市场方向代理和混杂，但 **A 不显著不能一票否决 B**，B 显著也不等于 A 有择时能力。 |
| 720 项归因作为第一步 | 不设为默认第一步。Codex 的候选集审计优先级正确：先检查 20 个因子从何而来、是否代表实际生产输入、覆盖哪些机制；之后再判断 720 归因能否改变决策。已存在的 0/720 应保留，不因归因选择而重定义。 |
| 用 Beta20 检查搜索表达能力 | 采纳为具体能力验证案例。当前代码能计算一部分 Beta 语义，但默认搜索生成和平台部署能力不同；应分别验收，不能以“注册了 Beta20”冒充“搜索器发现了 Beta20”。 |
| 任务 A 是任务 B 的混杂前置 | 部分采纳其诊断价值，不采纳其统一门槛地位。A 的结果作为 B 的解释变量/混杂诊断，不自动决定 B 是否允许检验。 |
| 分别建族 | 采纳“按假设族管理”，但分文件或分 `family_id` 不等于独立样本。若从 A/B/C 多个任务中择优宣布一个“最优门控”，跨任务选择仍须在设计中计入或用后续独立确认。 |

## 3. 新架构：按研究任务分线、共享特征底座

引擎底座按数据粒度与经济用途描述研究对象；**本轮实际任务聚焦 C（纯个股 Alpha 发现）和 B（个股 Alpha × 市场/行业状态交互）**。A（状态自身预测）与 D（独立风险/执行研究）仅保留为可扩展接口，不启动独立搜索；行业轮动继续独立研究。外部模型对照和 E3 属下游适配流程，不是所有候选的必经门。

| 任务 | 研究问题 | 候选与主要输入 | 产出 / 禁止的推断 |
|---|---|---|---|
| **A：状态自身预测（本轮不启动）** | 状态能否预测市场/行业收益或风险？ | MARKET/SECTOR 状态序列；需另行立项。 | 未来扩展接口；不作 B 的统一准入门，也不在本轮搜 standalone sector-regime 因子。 |
| **B：状态对 Alpha 的条件增量（当前交互任务）** | 个股 Alpha 在什么市场/行业状态下更有效？某个指定模型实验是否因此受益？ | 市场/行业上下文 × 版本化个股 Alpha 参考面板；历史 Top20、机制参考面板、外部模型实验分别登记。 | F1 类交互证据；需要经济结论时再接指定外部实验。不能把 `ΔIC` 或 h3 直接称为模型增量。 |
| **C：纯个股 Alpha 发现（当前主线）** | 表达式、论文机制、已有因子中是否有稳定横截面信号？ | `grammar.py` 机制搜索、refs、提案入口、未来 typed grammar。 | 个股因子候选与可复现评估；Top20 只是历史某轮筛选结果。 |
| **D：独立风险/执行研究（本轮不启动）** | 暴露或状态能否估计风险、改善可交易性？ | Beta、特质波动等因子可作为个股特征的计算 canary；完整风险/执行任务另行定义。 | 不把该类独立研究混入纯个股 Alpha/交互的当前预算与检验族。 |

**引擎主线裁定建议**：把纯个股因子 C 与市场/行业上下文交互 B 的候选生成、可计算性/数据契约验证、多保真评估、统计校准、筛选和可复现报告作为 merge 当前核心。A/D 不启动 standalone 搜索。Top1 交易表现由调用方提供模型/特征/数据切分 manifest 的外部运行验证，不将某次 Stage15 的175特征或日期边界烙进 merge 核心。

## 4. 从“因子类型”升级为多维特征本体

不要把 feature 作为单一 `STOCK` 或 `GATE` 枚举。一个特征应由多个正交属性描述，同一特征可在不同任务中有多个使用角色。

| 维度 | 推荐字段/值 | 例子 |
|---|---|---|
| **数据粒度 / 实体** | `STOCK×DATE`、`SECTOR×DATE`、`MARKET×DATE`、`CROSS_SECTION×DATE`、事件/横截面掩码 | `BETA20` 是股票×日；`MKT_RET` 是市场×日；`DISP` 可是行业×日并广播到股票。 |
| **经济语义** | `CROSS_SECTIONAL_ALPHA`、`MARKET_EXPOSURE`、`SECTOR_EXPOSURE`、`RISK_VOL_DRAWDOWN`、`REGIME_STATE`、`FLOW_LIQUIDITY`、`TRADABILITY`、`EVENT_ELIGIBILITY`、`RELATIVE_RESIDUAL` | Beta20 = 市场暴露/风险，不因可排序就自动成为 Alpha；行业收益排名 = 行业状态。 |
| **可承担任务** | `RANK_STOCKS`、`PREDICT_MARKET`、`CONDITION_ALPHA`、`CONTROL_RISK`、`FILTER_TRADABILITY`、`EXECUTION_DIAGNOSTIC` | `MKT_RET` 可用于市场预测或作为调制条件；只有在横截面定义合法时才可用于选股排序。 |
| **计算范围 / 广播方式** | 面板键、聚合实体、点时行业映射、是否广播、有效截面数 | 行业状态广播给成员股时，有效统计样本不能误当成股票总数。 |
| **时序与单位契约** | 输入字段、信号时间、可用时间、复权/基准定义、单位、窗口、warm-up、缺失/零方差规则 | 必须区分 `beta_20d` 所用 `000985.CSI` 与 merge 本地等权 `MKT_RET`；不能都只写“市场 Beta”。 |
| **计算/搜索/部署能力** | 分开记录 `local_eval`、`local_searchable`、`local_unit_tested`、`competition_verified`、`competition_uploadable`、`external_model_accepted` | `TS_REGRESS_BETA` 本地可算/可搜与能否上传是两种能力；竞赛不支持不影响 VWAP 搜索。 |
| **目标 / 估计对象** | 任务目标、预测期限、估计量/estimand、交易动作或统计终点 | `market forecast`、`gate×alpha` 条件效应、模型 add-one 和组合收益不是同一目标，不能共享未声明的分数门槛。 |
| **数据质量 / 访问权限** | PIT 状态、来源快照、读权限用途、质量等级、可否进入 discovery/confirm | “文件存在”不代表可用于当前任务；confirm/E3 数据默认拒绝 discovery、筛选、调参和人工排名读取。 |
| **身份 / 能力 / 证据状态** | 独立记录 canonical definition/version、各后端能力、候选生命周期/证据级别 | 本地可计算 ≠ grammar 可生成 ≠ 平台可运行；通过 discovery ≠ confirmatory ≠ 已改善外部模型。 |
| **运行血缘** | 数据快照/截止日、标签、宇宙与掩码、面板/家族 manifest、算子/语法版本、seed、预算、运行配置哈希 | 区分“定义相同”和“在新口径/新数据上测过”；允许复现、恢复和审计每一级筛选及淘汰。 |

`roles.csv` 的六类现有分类是有用的初始标签，保留并映射到新维度；升级不是把六类继续扩成几十个互斥类，而是避免**粒度、语义角色、下游用途、是否能搜索/上传**互相替代。字段/算子能力按执行后端记录：本地 VWAP evaluator 和 grammar 的准入不依赖 PandaAI 大赛的 `VERIFIED`/字段限制；`competition_uploadable` 仅供 C2C 导出/上传适配器使用，不是搜索时的拒绝条件。

候选的三类状态必须正交维护：**身份**描述候选/实验是什么，**能力**描述哪些执行后端能计算/生成/上传，**证据**描述目前只提案、卫生检查、发现评估、冻结待确认、独立确认或外部经济验证。任一状态不得从另一个状态推断。

## 5. 搜索表达能力：从固定网格升级为有类型约束的机制搜索

### 5.1 当前门控方案的定位

54 个基础量×操作化规格作为 **Gate Grid V1** 保留，作用是：

- 对已有候选基准可复现；
- 检查当前 G0/G2/G3/F1 管线的统计与工程行为；
- 为下一版机制搜索提供种子、对照和近克隆基准。

它不是“全部门控因子”。它覆盖了有限的方向中性市场/行业摘要量及四种时间操作化；没有系统表达股票级动态暴露、成分关系、横截面/时序交互、软状态转换，也没有把所有 QWIN 与转换组合展开。旧 M1–M4/S1–S3' 定义不恢复；旧定义已被用户裁定删除，其失败教训保留为约束。

### 5.2 新门控/调制搜索的候选结构

以带类型的 AST/计算图表示候选，而不是任意拼接字段。每个节点注明实体粒度与输出类型：

```text
可用原始量/已注册特征
  → 粒度内变换（滚动均值/波动/趋势/分位/变化/相关/回归）
  → 参照变换（自身历史分位、同日市场/行业横截面排名、行业相对量）
  → 状态表达（连续权重、预注册阈值、平滑开关/分段状态）
  → 用途：本地 VWAP 个股筛选 / 市场或行业状态 × 个股 Alpha 交互 /（可选）C2C 竞赛公式适配
```

`LOCAL_ONLY` 表示“不能由 C2C 平台公式执行器表达”，不是“不能进入 merge 本地搜索、评估或短名单”。

候选机制至少按以下轴维护配额和覆盖图，而非只看生成总条数：

1. **市场**：广度/扩散、横截面离散、领导股集中、波动/尾部、流动性/资金流、大小盘/风格轮动。
2. **行业上下文**：行业收益/相对强度、行业内离散、行业成交拥挤、行业风险扩散，可作为本地个股 VWAP 因子或交互因子的输入；**不能因 C2C 上传端无行业字段而从 merge search space 删除**。独立行业轮动研究仍按 PLAN D8 另行进行。
3. **股票级状态/暴露**：滚动 Beta、特质波动、残差动量/残差风险、个股流动性/跳空压力；这是当前 market/sector 两类没有覆盖的第三粒度。
4. **Alpha 条件形态**：连续调制、仅开仓/弃权门、两态/多态、行业内条件；每一种作用形式是独立研究定义，不是同一个 `form` 的无代价变体。

新生成器采用“机制模板种子 + 受约束变异/组合 + 固定预算”的混合方式：每个候选都能追溯到机制、输入、算子和参数；按机制给探索预算；先作不看标签的类型/缺失/稀疏/时间因果检查，再进入目标相关的发现评估；使用值指纹、秩指纹和结构指纹去重，但去重结果仅作为候选管理，不以相关高就宣称机制等价。

**不建议**把新基础量、窗口、转换、阈值、方向、标签、目标无约束笛卡尔积。扩容应按机制覆盖缺口提出；预先限制每种参数化的主值，登记版本和全部生成/拒绝事件。`--limit-gates` 继续是调试/分批控制，不是科学检验族边界。

### 5.3 算子增强路线与 Beta20 验证

当前能力应按“本地能算 / 本地能生成 / 能通过 C2C 竞赛执行器”分开。竞赛端是导出适配器，不决定本地 evaluator 的字段和算子空间：

| 能力层 | Beta20 当前状态 | 下一步 |
|---|---|---|
| 本地计算 | `ensure_local_fields()` 计算固定 60 日 BETA60；`TS_REGRESS_BETA(y,x,w)` 有通用本地求值路径。 | 用可控合成数据和独立 reference 实现验证 cov/var、滚动边界、全窗 warm-up、零方差、停牌/缺失、股票分组与无未来数据；再比较 `TS_REGRESS_BETA(RET1,MKT_RET,20)` 与独立 Beta20 实现。 |
| 默认候选生成 | 当前 M14/M16-context/M17 行业上下文模板需 `--local-context`；`run_search` 默认 profile 仍受 C2C 口径影响。 | 本地 VWAP profile 应默认开放通过 evaluator 语义测试的本地上下文字段/模板；Beta20 可作为 canary。是否能上传不参与 local ranking/淘汰。 |
| C2C 大赛上传 | `TS_REGRESS_BETA`、`MKT_RET`、`IND_RET`、`DISP` 属本地专用，`formula_uses_local` 在导出/上传适配器拒绝。 | 保留硬闸，仅拒绝该次竞赛批次；候选继续保留在本地 VWAP shortlist/ledger，并标注 `competition_uploadable=false`。 |

**粒度约束**：Beta20 是 `STOCK×DATE` 的暴露，不是每日所有股票共享的 `MARKET×DATE` 广播门。在本地 VWAP 搜索中可作为个股暴露或交互输入；若与 Alpha 交互，须另定 estimand、推断单位和 family，不能直接并入现有市场门控 F1v2 族。C2C 上传能力单独标记。

**VWAP 标签边界**：当前 `fitness.build_label_series(kind="vwap")` 是公式型本地标签：买入 `open(T+1)`，卖出 `0.7×TP(T+2)+0.3×TP(T+3)`。它与 `daily_atr_label.build_atr_label` 同公式，但后者另外应用 ST、可交易性、成交额和复权切换掩码；当前 merge `vwap` 未应用这些掩码。将 VWAP 设为默认 profile 不得静默改变此历史定义；run manifest/report 必须标明 `vwap_formula_only`，如需 tradability mask 应新增独立 label version 并单独校准。

算子实现/开放顺序：

1. **优先补表达能力而非算子数量**：打通 `RET1`、明确基准收益、Beta20/60、回归残差；必要时在 typed grammar 中增加受控 template。
2. **补跨粒度安全算子**：股票→行业/市场聚合、点时行业映射、同日横截面排名；输出必须保留样本键与实体数，行业序列的置换/重采样按日期保留整块横截面。
3. **再开放状态变换**：稳健滚动分位、状态阈值、软门/多段状态、趋势/变化/加速度。把参数范围、warm-up 和缺失规则放入 operator contract。
4. **每个算子分开登记能力**：本地实现存在 ≠ 语义测试通过 ≠ 进搜索生成 ≠ 平台已验证 ≠ 生产模型接受。`VERIFIED_OPS` 不能承担所有这些含义。

### 5.4 搜索预算、探索公平性与停止

搜索质量不能只用“产出多少候选”或“最高分是多少”衡量。每次运行在启动前应冻结预算合同，至少区分：

1. **提案/生成预算**：按任务 × 实体粒度 × 机制轴登记尝试生成数；记录生成、lint/type 拒绝、结构/值去重、进入快评、进入全评的各级数量及原因。提案、grammar 随机种子、精英变异、腿库重组分别记来源。
2. **计算预算**：分别记快评/全评候选数、行数、算子求值数、墙钟时间/峰值资源；按 AST 复杂度或实测成本估算，不默认每个公式成本相同。若有平台调用，再单独记 credits。
3. **覆盖预算**：每个预注册机制轴设置探索底额；历史 reward/UCB 只能在事先批准的总预算与轴下限内分配，不能让早期冠军轴把新机制挤出样本。未测轴、负证据、近因奖励与探索项均应写进分配记录。
4. **停止规则**：预算穷尽、候选覆盖达到目标、连续批次无增益、错误率/低质率过高等原因分别编码。`--stall` 仅为计算节省规则，不是统计无效或“已证明没有效应”的结论；手工提前停止也要落 ledger。
5. **校准要求**：只要 UCB、精英回流、历史奖励、人工提案或结果后追加搜索会影响下一轮候选分布，null/power 校准就必须复制相同的自适应流程；不能只校准最后一层 F1 p 值。

预算数值不在提案中凭空指定。Phase 1 先用当前运行成本、机制覆盖缺口与用户可接受的计算资源定首轮额度；额度、seed、分配算法和停止条件随后进入不可变 run manifest。`--limit-gates` 仍只作流程 smoke，不得被解释为科学族定义。

## 6. 搜索宇宙、参考面板与外部模型实验

### 6.1 四种对象、四种结论

| 对象/面板 | 用途 | 推荐地位 |
|---|---|---|
| **MergeFeatureUniverse**：全部有版本、语义/时序/能力元数据的可发现候选特征与基础字段 | 搜索器可表示什么、哪些输入/机制尚无覆盖 | 核心搜索目录；不是统计检验样本，也不意味着全量笛卡尔积评估。新增因子按质量和计算能力登记，不按同轮表现自动准入。 |
| **MechanismBalancedReference**：按事先定义的经济机制、来源、质量和冗余规则构造的版本化参考面板 | 比较搜索/状态交互在不同 Alpha 机制上的覆盖与迁移 | 研究评估面板。不得按同一待评估时段的 IC、F1 或模型结果选成员；每次变更产生新版本和新检验族。 |
| **HistoricalTop20**：`base20.json` / F1v2 成员 | 重现并解释已有历史结果 | 保留为历史探索基准；不扩写成整个 merge 搜索宇宙，也不作为门控价值的唯一正式标准。 |
| **ExternalModelExperiment**：调用方提供的一次模型/特征/数据切分/成本配置，如某次 Stage15 run | 回答“这批候选对这个指定模型实验有什么下游价值？” | 外部验证适配器。实验输入/输出需 versioned manifest；不同 run 可换因子、窗和模型。它不是 merge 的 canonical roster，也不阻塞 merge 搜索与筛选。 |

`roles.csv` 的124个 STOCK 列是现有目录事实，不等于整个 MergeFeatureUniverse，也不自动适合作为124×所有门控的确认族。不能从“Top20太窄”直接跳到“把124全部与所有门控做笛卡尔积”：先按任务定义搜索覆盖、参考面板、计算成本与统计单位。Stage15 某次使用175列、某次 CV 窗口或一次训练/测试切分均只对该 ExternalModelExperiment 负责，后续模型优化可以单独发生。

外部模型实验是经济价值验证对象，不天然是无偏统计确认面板。如果候选或模型版本曾用同一历史区间反复搜索、挑选或调参，在该区间上的结果仍属探索性/条件性证据。真正确认需要冻结后未参与对应选择链的数据。

### 6.1.1 新搜出的个股因子如何进入后续目录/面板

面板允许随 Alpha 搜索演进，但**不随结果自动滚动扩张**。对每个新因子按以下规则处理：

1. 先作为 Alpha 候选独立登记，核实经济语义、计算/点时正确性、有效覆盖、来源和冗余；不能因为它与某门控的交互显著才准入参考面板。
2. 若它填补机制平衡参考面板的预注册覆盖缺口，只有在**查看本轮交互结果之前**按固定准入规则加入下一版本 `MechanismBalancedReference_vN`。
3. 若调用方选定某次外部模型实验并愿意纳入该因子，精确记录该 run 的新 roster/config 和训练/测试切分；不回写为 merge 的全局生产 roster。
4. 新成员进入新 panel/family 版本；旧 family、旧成员哈希和旧结论保持不变。不得将新搜出的因子追加到旧清单后沿用旧 FDR 分母。
5. 若成员增添/更换是看过当前门控交互结果后的决定，新面板仍可用于后续探索；确认结论须等新的未触碰数据或明确覆盖整个适应选择链的设计。

因此答案不是“永远用旧 Top20”，也不是“每搜到一个因子就立刻加入同一统计面板”。新因子先进入候选目录；进入任何统计参考面板或外部模型实验时，都经由**明确规则、面板/运行版本和新检验族**。

### 6.2 F1 统计量要与部署动作对齐

当前定义 `F1=d·x·max(s·g,0)` 是**单侧正部加权/关门弃权**的策略形式。即使 `g=2p−1` 连续，`max(s·g,0)` 仍不是对完整连续状态的对称线性调节；G2 中的 `RankIC_t=a+b·g_t+e_t` 斜率与 F1 的正部交互估计的是不同对象。

新一轮必须在看结果前明确 B 的主 estimand。当前搜索 profile 以本地 VWAP 标签为主；C2C 可以同轮作为附加测量或单独竞赛 profile，但不能成为 VWAP 搜索、候选保留或短名单的必过门：

- **若产品动作是低状态弃权、高状态启用 Alpha**：保留正部门控为主候选，把阈值/门控方向/权重形式预注册；
- **若问题是状态如何连续改变 Alpha 能力**：把完整连续交互（例如 Alpha×中心化状态）的斜率/边际效应定为主估计量；单侧开关作为另一种策略假设；
- **若问题是 Top1 交易改善**：统计交互指标只作筛选层，最终主终点在生产模型对照中冻结。

这些形式不能在结果出来后选最好者再称“斜率尺”。多种形式都试时，必须加入候选家族/预注册或在全新确认段验证。因子大赛的字段限制只能在 C2C 的导出/上传处过滤，不得反向限制本地 VWAP 候选生成与统计评估。

## 7. 评估、筛选与证据层级

### 7.1 共享的管道骨架

```text
注册特征与数据契约
  → 按任务生成候选（Alpha / 状态预测 / 条件调制 / 风险执行）
  → 结构、类型、因果、缺失、覆盖和重复检查（不看结果标签）
  → 按预先冻结的机制/计算预算做 discovery 与多保真筛选（只用于选择候选）
  → 冻结成员 + estimand + 数据窗 + 算法 + 族清单
  → 筛选器校准 + confirmatory 统计检验（未被选择流程看过的数据；或明示 E1 探索性）
  → 可选外部模型/交易经济对照（merge 外、按 run manifest 隔离）
  → 冻结候选与配置，之后才有资格积累 E3 前向确认
```

### 7.2 各层的职权

| 层 | 应回答 | 应做 | 不应做 |
|---|---|---|---|
| **工程/类型** | 候选是否定义完整、无前视、可求值、粒度合法？ | AST/type check、单位/范围、warm-up/coverage、点时映射、panel/hash 血缘、语义测试。 | 用 IC/p 值判断合法性，或因统计结果改数据契约。 |
| **廉价候选筛选** | 哪些候选明显退化、错误或无覆盖？ | G0/稀疏/结构/排序等价检查；快评可排序；在冻结样本上估计各机制的错误淘汰率、保留率、全评资源节省。 | 未经筛选器校准就将快评阈值当通用规则；把同一发现集 G2/G3 选出的候选再当作未经选择的确认集。 |
| **任务 A：状态自身评估（本轮不启动）** | 市场/行业状态对预注册未来目标是否有效？ | 若后续立项，按市场日或日期×行业的正确抽样单位处理时序/截面依赖。 | 本轮把 A 扩成 standalone search；把 A 的不显著当成 B 的禁入。 |
| **任务 B：条件增量（当前交互任务）** | 预定义个股 Alpha 参考面板在市场/行业上下文条件下是否改善？ | 对冻结的 alpha/context/形式/方向/窗口全族评估；报告效应量、CI、块稳定、placebo、FDR。 | 只保留当前 Top20 后宣称代表全体 Alpha；只报名义通过者；把 `ΔIC` 叫作模型增量。 |
| **外部经济/模型对照** | 候选对某个指定模型实验/交易策略是否有下游价值？ | 由外部执行器输入具名的 baseline/enhanced 配置、数据切分、特征/掩码、训练预算、交易成本与 manifest；报告该次实验的 Top1/净收益、回撤、换手和稳定性。 | 把某一次 Stage15 roster/CV 硬编码为 merge 的目标或固定确认族；把 LightGBM 诊断移进 merge skill。 |
| **前向确认 E3** | 冻结流程在完全未参与选择的数据上是否保留效果？ | 冻结模型/特征/任务定义后，等标签成熟后运行；保留独立事件日志。 | 用已在搜索或 holdout 排名中参与决策的日期称“独立前向”。 |

### 7.3 `h3`、FDR 与检验族

- `h3_pass` 当前是三项名义规则的合取（CI 下界、至少 4/6 块为正、placebo p<0.05）；它不是一个独立流水线阶段，也不等于校正后显著。
- `judge_f1.py` 当前对输入族中的 `placebo_p` 做 BH-FDR，另存 `fdr_q/fdr_sig`。结果应同时报告 **h3** 和 **FDR**，并明确 S8 资格要求是否二者都必须满足。
- 多重检验族应至少绑定：任务、候选 ID/定义 hash、市场/行业/股票粒度、Alpha 面板版本、方向、门控形式、阈值/窗口/QWIN、标签与期限、估计量、置换/块设定、时间边界、清单版本。当前 `members_hash=(gate,base,s)` 是成员校验，不是完整研究设计哈希。
- 如果在同一数据上先用 G2/G3、rank/topn、人工查看结果挑候选，再只对幸存者做 F1，F1 的名义族 FDR **不会自动校正这整条自适应选择链**。正式办法二选一：
  1. discovery 阶段允许自适应选门控；冻结后在未参与挑选的 confirm 时间段，对冻结成员运行确认族；或
  2. 对全部实际被选择/比较的检验整体计入确认规则（计算成本更高），不把前置筛选当作免费。
- **全链路校准**：null 与 power 仿真要复现候选提案/生成、UCB 配额、精英回流、lint/预筛、快评阈值、全评截断、人工/自动停止与家族构造；报告整体 FDR/误发现、筛选器假阴性率、效应偏差、区间覆盖率和功效。只校准末层 `judge_f1` 不能校准搜索/筛选引擎。
- A/B/C/D 可有各自问题明确的族清单，但共用数据且最终跨任务择优时不能宣称统计独立。跨任务的“挑最终赢家”要么在总设计里控制，要么只作发现并交给独立前向段确认。
- `f1_family.py` 的成员逐一对应与哈希约束值得保留并拓展；新设计不应通过拆成多个小 manifest 来规避整体搜索的多重性。

### 7.4 市场、行业、股票级状态的不同统计单位

- **市场级**：`g_t` 是每日一个值；时间日期是核心独立抽样轴，使用保留时间依赖的重采样。
- **行业级**：`g_{s,t}` 是日期×行业面板；同日行业受共同市场冲击。重采样应以日期块为单位并保留该日完整行业向量；行业成员变化和行业映射必须点时定义。不能把 131 个行业在同一天当作 131 个独立日期。
- **股票级暴露**：`g_{i,t}` 可因股而异（如 Beta20），不等于市场广播门。条件增量的估计样本、聚类方式、截面可比性需单独设计。
- **方向/收益代理诊断**：只对 B 的条件效应解释是否被市场方向/风险暴露解释；不能以“所有状态必须方向中性”抹掉任务 A 中本来允许方向性的择时/风险目标。

### 7.5 实用效应下限与门控级汇总

**实用性需要预注册，但不采用未经校准的硬阈值。** 统计显著不等于交易上有价值；反过来，在未将 `ΔIC` 与 Top1 的经济收益建立稳定映射前，也不能凭空规定“`ΔIC<0.02` 就淘汰”。

- Phase 1 应提出并验证一个可解释的最小实用效应（MDE）：优先在外部生产对照指标中定义（Top1 净增量、回撤/换手约束等）；若要把它投影到 F1 的 `ΔIC` 单位，必须用预先冻结的映射/历史仿真标定，并记录不确定性。
- 若校准完成，可在确认设计中预注册 futility 规则：例如估计区间上界仍低于该 MDE 时，判为“达不到预定义实用价值”，而不是改写为“统计上不存在效应”。**未校准 MDE 时只报告效应与区间，不在 `judge_f1` 中加任意数值硬门。**
- **Pair 级口径**（gate×alpha）继续回答“哪些具体组合有效”；另预注册一个 **gate 级面板汇总 estimand**，回答“该门控是否对预定义面板整体有一致价值”。汇总应先按机制报告，再给面板级 summary；同一日期块对所有因子共同重采样，以保留因子间相关性。
- Pair 级与 gate 级结果并列，不把高度相关的 Alpha 当作独立选票；不使用未经校准的 Fisher 合并或简单计数代替依赖结构。确认前需冻结 effect 标准化、因子面板权重/机制权重、缺失规则、门控级族范围和重采样方法。
- Gate 级“面板总体效应”只对**该固定面板**成立；MechanismBalancedReference 的样本代表性有限时，不外推成“对全部未来 Alpha 有效”。

### 7.6 排序分、证据状态与筛选器质量

1. **硬有效性**只回答候选是否合法、可计算、点时/单位/粒度正确；**搜索排序分**只用于分配有限计算预算；**统计资格**由冻结估计量与检验族决定；**外部经济验证**由调用方另行运行。四种输出要分字段，不允许一个 `rank_score` 同时充当合法性、显著性和部署准入结论。
2. 搜索排序可保留当前启发式分，也可比较 Pareto/稳健排序；报告各原始指标、估计不确定性和排序规则版本。复杂度、稳定性、换手、创新度、池相关性可作为独立维度；权重/硬门槛须在使用前冻结并可做敏感性分析。
3. 快评对全评的误差必须按候选机制、实体粒度、复杂度和效应区间分层校准，报告 false-negative/false-positive、排序相关、保留率和单位资源节省。存在机制盲区时使用轴级保留名额或将该类候选直接送全评，不能用总体相关系数掩盖分层漏检。
4. 所有生成、拒绝、跳过、失败、超时、复用和提前停止事件写入 run manifest/ledger；重跑能以相同语法/数据版本/seed 恢复候选集合，并能从最终名单反查每一个候选的来源与路径。

## 8. 推荐的端到端版本

### Phase 0：merge 引擎事实审计（不扩容、不新增确认性实验）

1. 绘制实际端到端路径：纯个股模板/随机树/变异与交叉、精英/腿库、LLM或人工 proposal、refs、以及个股×市场/行业交互 Gate Grid → parser/type/lint → fast → full → rank/shortlist → F1/G2/G3 → report/export。标明本地 VWAP 与 C2C 适配分支，逐级记录入口、身份键、拒绝原因、评分、输出与成本；standalone 行业轮动不纳入当前范围。
2. 清点**表达覆盖**而非只点算子数：基础字段/现成因子 × 机制 × 实体粒度 × 时间变换 × 交互形态；区分本地已实现/可求值/可生成/已测试，与 C2C 可表达/已上传。行业数据在本地可用与否按本地 cache/evaluator 判断，不能由平台字段目录代替。Beta20 作为一项 canary。
3. 清点**评价/筛选合同**：标签与期限、样本宇宙/周期、direction、快评与全评窗、硬拒绝与软排序、F1/G2/G3 族、pair/gate 估计量；检验排序分、名义统计指标、FDR 与经济结论是否被混用。
4. 只读审计已有筛选校准与运行成本产物；现有 fast-vs-full benchmark 与 F1v2 h3/FDR 归因仅作基线/描述，不重跑候选、不重算 p 值、不据此改面板。`base20` 的生成器暂未找到时保留为历史参考，不阻塞 merge 宇宙设计。
5. **落实数据访问审计**：分别记录“文件/row group 物理可读”“入口读取到内存”“裁剪后进入 evaluator”“进入候选评分/选择”四种状态。当前 raw cache 有 2026-10-13 版本；merge 自动发现当前选用到2026-09-18的 cache，而 `boundary_log.jsonl` 有 595 事件、其中229条的源文件最大日大于返回最大日（最高2026-10-12）。这证明了结果路径裁剪，不证明物理封存；E3 日期禁止被称为全局未触碰，直至实现与审计目的型访问控制。
6. 固化搜索基线、现有 manifest/ledger/配置和Git状态；现有 F1v2 720、Gate Grid V1 54、历史角色表与代码版本留作可复现基准。
7. Stage15 只登记一个 `ExternalModelExperiment` 快照（含其 manifest/结果路径），不追求确定一个永久生产 roster，不优化其切分/因子池，不将其作为 merge Phase 0 的阻塞项。

**验收**：任何候选能追溯从来源至结论的完整路径；清楚区分硬门、排序与统计；能量化候选漏斗/资源成本；数据访问表区分物理可读和实际使用；Stage15 被记录为一轮外部实验而非全局标准；不扩族、不把 F1v2 推广成总门控结论。

### Phase 1：冻结 merge 引擎合同（规格决策，不绑定单一 Stage15 run）

1. 冻结当前实施目标为纯个股 Alpha 发现（C）与个股 Alpha × 市场/行业上下文交互（B）；**本地 VWAP 是默认主 profile**，C2C 是可选竞赛 profile；A/D 仅记录为未来接口，不在当前预算里独立搜索，遵循 PLAN D8。
2. 冻结最小 Feature/Candidate/Run manifest：粒度/机制/来源/点时/数据质量/能力后端；canonical AST/spec、语法版本、数据快照/窗口、标签/宇宙/掩码、seed、父代/提案、每阶段预算及退出原因。
3. 明确能力、生命周期和证据状态；本地可算/可搜不要求 C2C 可表达；`competition_uploadable` 只控制导出/上传。`rank_score` 及 UCB 仅负责搜索资源/候选排序，不能代替统计资格、family 校正或部署决定。硬失败与软低优先级分开。
4. 为每个机制/粒度冻结第一轮总预算、最小探索配额、fast/full 名额或成本上限，以及停止条件；UCB 可在预设边界内调整，不允许事后无限续搜。
5. 定义每项任务的统计契约（目标、estimand、抽样/聚类单位、依赖、缺失处理、效应量/区间、null、检验族、预注册与确认路径）。MDE 有业务解释且经过映射校准后才成为 futility 规则；未经校准只报告效应与区间。
6. 将确认数据池列为**目的型访问权限**：discovery 默认无权读；confirm 需冻结 manifest、指定候选族和标签成熟边界，默认拒绝；权限在原始读取层生效并记录访问事件，而非读取全部文件后只在 DataFrame 过滤。
7. 定义 VWAP profile 的标签/评分/短名单合同和 C2C profile 的竞赛指标/上传合同；明确多标签诊断不互设必过门。外部模型实验接口接受调用方 manifest（模型哈希、输入特征、split、mask、cost、metric、输出哈希），但不要求某个 Stage15 版本/roster。

**验收**：引擎合同不依赖 Stage15 固定因子池/切分；候选/实验可复现；任务间 metric、预算、状态边界不混；确认集物理不可读或必须显式授权；任何模型对照均可被精确归属到某一外部 run。

### Phase 2：建立 evaluator 与筛选器的可验证基准

1. 对 evaluator 每个运算符建立小型独立参考实现和合成夹具：边界/warm-up、缺失、零/常数、停牌/缺交易日、分组排序、点时性、尺度和浮点容差。
2. 在已知 null 与注入效应的合成面板上检查每个统计量/CI/placebo/FDR：覆盖时间自相关、截面相关、机制相关、非平稳、稀疏并列、缺失和市场/行业/股票不同粒度。
3. 对快评→全评采用冻结 benchmark 面板，按机制/复杂度/信号强度分层报告误差、假阴性、假阳性、秩相关、throughput 与成本；根据漏检成本设定是否直接旁路快筛。
4. Beta20 可作为本地回归算子的 canary：逐值对拍 cov/var、基准收益、窗口、warm-up、零方差和缺失；能力矩阵分别记录 evaluator、grammar、CLI、平台能力。

**验收**：测试能在已知真值时发现实现/筛选错误；测量结果有固定 seed 与完整配置；无阈值因真实候选结果事后调整；本阶段不使用/解封 E3，也不触发平台调用或大规模因子验证。

### Phase 3：统一候选规划与机制搜索

1. 为公式因子 AST、门控规格、外部因子与 LLM/人工提案建立统一的 provenance/run interface；保留各自语法和专业后端，不强求不同实体共享同一表达式语法。
2. 把 Gate Grid V1 54 规格与现有 grammar 种子保留为版本化 baseline；逐步增加本地个股与 market/industry context × stock Alpha 的交互覆盖，依据 Phase 0 缺口逐项立项；C2C uploadability 不参与 local candidate generation。
3. 将固定预算、轴探索底额、UCB、精英回流、组合重组与历史失败经验放在统一 SearchPlan 中；每个随机/自适应分支可复现、可停止、可在同预算下比较。
4. 结构/值/秩指纹只用于重复候选管理；不得因为统计相关高就直接宣布机制相同或删除不同任务的候选。

**验收**：相同 manifest/seed 可复现候选集合与父代链；每一拒绝/重复/预算跳过均有原因；机制/粒度的探索底额得到满足；当前 54 网格和 grammar 基线可作为对照重跑。

### Phase 4：多保真筛选、统计族与全链路校准

1. discovery 可使用 G0、快评、G2/G3、UCB 与 Pareto/任务排序；所有自适应淘汰只降低后续优先级或减少预算，除非筛选器已按机制校准至预注册的错误率目标。
2. 冻结确认成员和完整 family manifest 后，才在授权 confirm 数据上运行；无合格未触碰窗口则明确标为 E1 discovery，不借旧 holdout 或外部模型实验包装为确认。
3. 零效应和注入效应 simulation 复现**整个搜索与选择链**（生成、拒绝、筛选、排序、预算、停止、选择检验族），测量 family FDR/FWER、false-negative、偏差、覆盖率和 power。
4. 门控任务报告 pair-level / gate-level；因子发现报告单因子与去冗余/组合边际。检验族包括所有会被选中、比较或作为终结论挑优的假设；拆小 manifest 不缩小实际选择家族。

**验收**：预注册测试族与流水线实际比较集逐一对应；筛选器在真实候选之外有明确、分层的误差校准；没有把 adaptive search 输出直接称为确认结论。

### Phase 5：任务适配器与外部验证

1. 当前优先交付 stock Alpha 与 market/industry-context × stock Alpha 的 VWAP profile；C2C competition profile 复用候选和评估底座，但以能力标签过滤导出列表。独立行业轮动/A/D profile 另行立项。
2. 外部生产模型/Top1 对照采用 plug-in manifest；某个 Stage15 run 可用作一个具体对照，用户之后可以另行优化它的因子池和数据切分，不影响 merge 核心搜索合同。
3. 只有当冻结的任务、候选和外部模型配置具备独立数据并实施了目的型访问隔离后，才启用 forward/E3 结论。

**验收**：工程、统计、外部经济、前向状态分别报告；一层结果不能越级改写另一层结论；模型级增量继续在 merge 外运行。

| VWAP 标签语义 | 初始默认维持 merge 当前 `vwap_formula_only` 定义；显式记录其与 `daily_atr_label` tradability/ST/复权 masks 的差异。 | 若改成带交易掩码的 VWAP，需作为新 label 版本并重校，不静默改变历史 `vwap` 读数。 |
| 外部模型实验 | 调用方选择任一具名模型 run，提供模型、输入列、数据切分、mask、cost 和输出 manifest；Stage15可为一次样本。 | 实验结论只适用于该配置；Stage15 因子池/数据窗后续可专门优化，不阻塞 merge。 |
| 首个 evaluator canary | Beta20 是本地滚回归语义/边界测试案例之一；另外覆盖 MKT_RET/IND_RET/DISP、缺失、零方差与稀疏信号。 | 单个因子成功不替代全 evaluator/operator contract 验收。 |
| 任务主估计量 | 每个 Task Profile 分别冻结目标、抽样单位、estimand、主/次指标、依赖处理与检验族；门控任务可并列 pair/gate 级。 | G2 线性斜率、F1 正部交互与经济模型增量不是同一 estimand。 |
| 确认性数据 | 按用途隔离并留痕；无合格未触碰数据时，只报告发现/探索，不承诺确认。 | 当前有新 raw cache 文件且边界层存在读宽后裁剪，不能仅凭常量称 E3 全局未触碰。 |

**建议的第一批工作顺序**：Phase 0 merge 漏斗/数据访问/成本审计 + 现有720结果零成本归因 → Phase 1 冻结本地 VWAP 主 profile/C2C adapter、candidate/evaluation/budget/data-permission contracts → Phase 2 evaluator 与 fast/full 校准夹具 → P0 改默认 profile 与 local-only 短名单路径 → Phase 3 扩充机制覆盖。先校准和保护现有能力，再有预算地扩机制空间。

### 首批可直接实施的 P0（不改统计阈值、不调用平台）

1. **profile 与目标**：`run_search.py` 明确 `local-vwap` / `competition-c2c` profile；无参数默认本地 VWAP。VWAP profile 以现有本地 `rank_sia` 排序，默认不套用 C2C 的 SiA、turnover floor、platform prior 或 OOS 触发阈值；C2C 的 fast SiA 门也不作为 VWAP 默认门。现有 `--label` 保留为附加测量/兼容旧命令，不让 C2C 标签成为 VWAP 的隐式主分数或必过门。VWAP 沿用 merge 当前公式型定义并标记 `vwap_formula_only`，本变更不静默添加交易掩码。
2. **本地搜索能力**：搜索默认开放已登记且通过本地语义测试的上下文字段/模板（含 `IND_RET`、`DISP`、`MKT_RET`），LLM/人工 proposal 与 intake 走同一本地能力合同；`--no-local-context` 可用于对照。平台不兼容只是 backend 能力属性，不是 evaluator/fast/full/local shortlist 的拒绝条件。
3. **多标签分轨**：主 shortlist 按 profile 目标排序；有相应标签结果时额外输出 `vwap_top` 与 C2C 竞赛候选视图。C2C 结果不对 VWAP 设硬门；VWAP 结果也不被误称为竞赛指标。
4. **按目标隔离搜索记忆**：UCB reward 默认跟随 primary profile（VWAP 使用 rank_sia）；腿库/精英回流、提案排除、自动失败知识回流和变异分支统计按 label/profile + `data_cut` 隔离；VWAP 自动失败阈值未校准前禁用其 auto-fail 回流；C2C `platform_prior` 不作用于 VWAP。
5. **上传边界只在 adapter**：`cmd_export`/`cmd_upload` 按 `competition_uploadable` 过滤，先过滤再 top-N 截断；没有 C2C 指标或可上传候选时清晰拒绝导出。所有 local-only 候选仍保留在本地候选池、ledger 与 VWAP 报告。
6. **最小回归验证**：小型合成候选证明含 `IND_RET` 的公式能通过本地 VWAP 评估/短名单、不会进入 C2C 上传批次；平台兼容公式仍可导出；profile、UCB reward、evidence pool、report 跟随目标。只用合成面板，不跑真实因子检验或平台请求。

该变更集完成后，再做 vwap/evaluator 语义与 fast/full 筛选校准；不在 P0 改 vwap 标签公式、统计阈值或历史检验族。

### 执行防漂移约束

- **Owner**：研究负责人（用户）决定引擎验收目标、统计/确认政策和资源预算；实现/审计执行者提供代码与运行证据；外部模型实验调用者提供每次 run 的 manifest。没有 run manifest 时，不把外部模型结果并入 merge 结论。
- **建议 timebox**：Phase 0 在依赖输入就位后10个工作日内交付 merge 引擎审计；Phase 1 在审计后5个工作日内形成可签核的任务/预算/数据权限清单。Stage15优化工作不放进此时限。
- **阶段闸门**：Phase 0/1 未完成，不做大规模候选扩容；Phase 2 语义/筛选校准未通过，不以 fast 门作为强淘汰；确认样本不存在时，结果标探索性，不以开发样本临时代替。
- **文档归并**：用户批准方案后，只把批准的规范并入 `MERGE_V2_PLAN.md` 的正式新节，并更新 `TECHNICAL.md` 的实现事实；本提案随即标为已替代，避免出现第四个持续漂移的架构来源。
- **Git 变更保护**：V3 基线已建立并推送；后续只对本任务相关文件逐项审查、保留可复现 manifest，不批量暂存用户工作，不将原始大数据提交到 Git。历史清理/重写仍需单独授权。
