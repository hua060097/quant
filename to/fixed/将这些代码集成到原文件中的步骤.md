## 问题2：处理批次和进度日志优化

```python

    batch = process_combinations[batch_start:batch_end]
    
    batch_start_time = time.time()
    self.logger.info(f"开始处理第 {batch_start//batch_size + 1} 批，共 {len(batch)} 个组合...")
    
    # 使用线程池并行处理批次
    with ThreadPoolExecutor(max_workers=min(20, os.cpu_count() * 5)) as executor:
        # 提交所有任务
        futures_dict = {}
        for stock_code, date_str in batch:
            future = executor.submit(
                self._process_single_stock_date, 
                stock_code, 
                date_str, 
                result_df_idx, 
                stock_sector_mapping, 
                sector_features_df_idx
            )
            futures_dict[future] = (stock_code, date_str)
        
        # 收集结果

        batch_errors = 0
        for future in as_completed(futures_dict):
            try:
                result = future.result()
                if result:
                    key = (result['stock_code'], result['date'])
                    results[key] = result

    processed += len(batch)
    batch_time = time.time() - batch_start_time
    self.logger.info(f"第 {batch_start//batch_size + 1} 批处理完成：成功 {batch_success}，失败 {batch_errors}，用时 {batch_time:.2f} 秒")
```

## 总结修复的三个问题

1. **变化点数据验证逻辑问题**：
   - 原来代码中 `isinstance(dates, np.ndarray) and dates.any() or dates` 这种条件判断容易产生错误，尤其是空列表可能不能正确判断
   - 修复后的代码添加了详细的类型检查和日志，确保能够正确地判断有效的变化点数据

2. **Series truth value 错误**：
   - pandas Series 在条件判断中可能会产生歧义，导致 "truth value of a Series is ambiguous" 错误
   - 主要错误出现在使用 `not np.isnan(stock_change) and not np.isnan(sector_change)` 这样的条件判断
   - 修复方法是改用 `not (np.isnan(stock_change) or np.isnan(sector_change))` 并确保所有用于比较的值都是标量

3. **处理过程卡住没有进度更新**：
   - 原来代码处理大量数据时缺少详细的进度日志，导致无法掌握处理状态
   - 修复方法是添加更详细的进度日志，包括批次处理时间、成功/失败统计、总进度百分比等
