# Tushare 批量下载 Bug 分析报告

## 问题描述

使用 `ts.pro_bar()` 批量下载股票数据时，发现数据量异常膨胀。

## 测试结果汇总

### 测试1: 单个股票下载 (adj='qfq')
```python
ts.pro_bar(ts_code="000001.SZ", adj='qfq', start_date="20260109", end_date="20260109")
```
- **结果**: 1 条记录 ✓ 正确

### 测试2: 批量下载 2 只股票 (adj='qfq')
```python
ts.pro_bar(ts_code="000001.SZ,000002.SZ", adj='qfq', start_date="20260109", end_date="20260109")
```
- **结果**: 4 条记录 (每只股票 2 条) ✗ 错误
- **数据示例**:
  ```
  000001.SZ  20260109  11.53  11.46
  000001.SZ  20260109  15.57  15.47  (重复！)
  000002.SZ  20260109   4.87   4.96
  000002.SZ  20260109   6.58   6.70  (重复！)
  ```

### 测试3: 批量下载 3 只股票 (adj='qfq')
```python
ts.pro_bar(ts_code="000001.SZ,000002.SZ,600000.SH", adj='qfq', start_date="20260101", end_date="20260109")
```
- **结果**: 45 条记录 (每只股票每天 3 条) ✗ 错误
- **预期**: 27 条记录 (3只股票 × 9天)
- **实际**: 45 条记录 (3只股票 × 5天 × 3条/天)
- **数据示例**:
  ```
  000001.SZ  20260109  11.53  11.46
  000001.SZ  20260109  15.57  15.47  (重复！)
  000001.SZ  20260109   1.42   1.41  (重复！)
  ```

### 测试4: 批量下载 + adj=None (不复权)
```python
ts.pro_bar(ts_code="000001.SZ,000002.SZ", adj=None, start_date="20260109", end_date="20260109")
```
- **结果**: 2 条记录 (每只股票 1 条) ✓ 正确

## 根本原因

**Tushare 批量下载模式的严重 Bug**:

当使用 `ts.pro_bar()` 且同时满足以下条件时：
1. **批量模式**: ts_code 为多个股票代码（逗号分隔）
2. **价格复权**: adj='qfq' 或 adj='hfq'

API 会返回 **N 条记录/股票/天**，其中 N = 批量请求中的股票数量！

| 批量股票数 | 每只股票每天的记录数 |
|----------|------------------|
| 1 只     | 1 条 ✓           |
| 2 只     | 2 条 ✗           |
| 3 只     | 3 条 ✗           |
| 500 只   | 500 条 ✗         |

**这就是为什么用户下载 500 只股票时，数据量是预期的 277 倍！**

## 数据膨胀计算

用户场景:
- 500 只股票
- 9 天数据
- 预期: 500 × 9 = 4,500 条

实际（使用 adj='qfq' 批量下载）:
- 每只股票每天: 500 条记录（因为批量了 500 只股票！）
- 总数: 500 只 × 9 天 × 500 条/天 = **2,250,000 条**
- 膨胀倍数: 2,250,000 / 4,500 = **500x**

与实际观察到的 277x 倍数接近（可能有些股票停牌或部分日期缺失）。

## 解决方案

### 方案1: 保持单股票下载模式（当前方案）✓ 推荐
**优点**:
- 数据正确性有保证
- 支持前复权/后复权

**缺点**:
- 速度较慢
- API 调用次数多

**实现**: 已在 download_daily.py (lines 176-214) 中实现

### 方案2: 批量下载不复权数据 + 自己复权
**优点**:
- 批量下载速度快
- 数据正确（adj=None 时批量模式正常）

**缺点**:
- 需要自己实现复权逻辑
- 需要下载除权除息数据
- 实现复杂度高

**实现**:
```python
# 批量下载不复权数据
df = ts.pro_bar(ts_code=batch_stocks, adj=None, start_date=start_date, end_date=end_date)

# 使用除权除息数据进行复权
# （需要额外获取复权因子数据）
```

### 方案3: 混合方案 - 小批量 + 去重
**优点**:
- 速度中等
- 通过去重保证数据正确性

**缺点**:
- 仍然会有冗余下载
- 需要额外的去重逻辑

**实现**:
```python
# 使用小批量（如 5-10 只股票）
small_batch = stocks[i:i+10]
df = ts.pro_bar(ts_code=','.join(small_batch), adj='qfq', ...)

# 严格去重 - 保留第一条记录
df = df.drop_duplicates(subset=['ts_code', 'trade_date'], keep='first')
```

## 最终建议

**继续使用方案1（单股票下载模式）**，原因：

1. ✓ 数据正确性是最重要的
2. ✓ 虽然慢一些，但可以接受
3. ✓ 避免了 Tushare 的批量模式 bug
4. ✓ 支持完整的价格复权功能

如果未来需要优化性能，可以考虑：
- 使用多线程/多进程并行下载
- 缓存机制减少重复下载
- 考虑切换到其他数据源（如 akshare）

## 结论

**Tushare 的 ts.pro_bar() 在批量模式 + 价格复权时存在严重 bug，导致数据膨胀 N 倍（N=批量股票数）。**

**当前解决方案**: 使用单股票下载模式，虽然较慢但数据正确。
