# 数据缓存系统使用说明

## 系统概述

数据缓存系统是一个专为量化回测框架设计的高性能数据访问层，通过多级缓存机制显著减少对底层数据API的调用次数，提高回测速度和效率。该系统无缝集成到现有回测框架中，支持自动数据预加载、智能缓存管理和性能监控。

## 主要特性

- **多级缓存架构**：内存缓存和磁盘缓存组合，提供最佳性能和持久化
- **透明数据访问**：使用与原始API相同的接口，对上层应用透明
- **智能缓存管理**：基于LRU策略的内存管理，自动清理不常用数据
- **并行数据预加载**：支持多线程并行加载数据，大幅减少回测准备时间
- **性能监控**：实时跟踪缓存命中率和性能提升
- **自动内存限制**：防止内存占用过大，自适应系统资源

## 系统组件

数据缓存系统由以下主要组件构成：

1. **数据缓存管理器(`DataCacheManager`)**：核心组件，负责数据的存取和缓存管理
2. **缓存元数据**：记录磁盘缓存的索引和使用统计
3. **内存缓存池**：快速访问的一级缓存，存储热点数据
4. **磁盘缓存池**：持久化的二级缓存，存储大量历史数据
5. **性能监控系统**：收集和报告缓存使用统计信息

## 快速入门

### 基本使用

在回测脚本中使用数据缓存系统：

```python
# 导入数据缓存管理器
from data_cache_manager import get_data_cache_manager

# 获取数据缓存管理器实例
cache_manager = get_data_cache_manager()

# 使用缓存获取市场数据
market_data = cache_manager.get_market_data(
    stock_list=['000001.SZ', '600000.SH'],
    field_list=['open', 'high', 'low', 'close', 'volume'],
    period='1d',
    start_time='20230101',
    end_time='20230131'
)

# 使用缓存获取交易日期
trading_dates = cache_manager.get_trading_dates(market='SH')

# 获取单个股票的价格
price = cache_manager.get_stock_price('000001.SZ', '20230105', 'close')
```

### 数据预加载

在长时间回测前预加载数据可以显著提高性能：

```python
# 普通预加载
preload_stats = cache_manager.preload_data(
    stock_list=stock_universe,  # 股票代码列表
    start_date='20230101',      # 开始日期
    end_date='20230630',        # 结束日期
    fields=['open', 'high', 'low', 'close', 'volume'],  # 字段列表
    periods=['1d']              # 时间周期
)

# 并行预加载(推荐用于大量股票)
parallel_stats = cache_manager.parallel_preload(
    stock_list=stock_universe,
    start_date='20230101',
    end_date='20230630',
    fields=['open', 'high', 'low', 'close', 'volume'],
    periods=['1d'],
    batch_size=50,              # 每批处理的股票数量
    max_workers=8               # 并行线程数
)
```

## 回测框架集成

数据缓存系统已无缝集成到现有回测框架中：

1. **自动初始化**：回测框架启动时自动初始化缓存系统
2. **透明调用**：框架内部的数据获取自动转向缓存系统
3. **性能报告**：回测结束时生成缓存性能报告

使用者不需要修改现有代码，系统会自动利用缓存功能。

## 配置选项

数据缓存系统支持以下配置选项：

```python
# 自定义配置
cache_manager = get_data_cache_manager(
    cache_dir="to/data_cache",  # 缓存目录位置
    memory_limit_mb=2000        # 内存限制(MB)
)
```

可配置项说明：

- `cache_dir`：缓存文件存储目录，默认为`to/data_cache`
- `memory_limit_mb`：内存缓存最大使用内存，单位MB，默认为2000MB

## 性能优化建议

为了获得最佳性能，建议：

1. **预加载关键数据**：回测前预加载整个回测区间的数据
2. **使用并行预加载**：当加载大量股票数据时使用并行加载
3. **适当设置内存限制**：根据系统可用内存设置合理的缓存大小
4. **定期清理过期缓存**：使用`clear_cache`方法清理不再需要的缓存数据

## 性能监控

可以随时获取缓存系统的性能统计信息：

```python
# 获取缓存统计
stats = cache_manager.get_stats()
print(f"缓存命中率: {stats['hit_rate']:.2f}%")
print(f"内存使用: {stats['memory_usage_mb']:.2f}MB")
print(f"缓存项数量: {stats['memory_items']}(内存), {stats['disk_items']}(磁盘)")

# 生成完整性能报告
cache_manager.generate_performance_report()
```

## 进阶功能

### 缓存清理

当需要清理缓存数据时：

```python
# 清理所有缓存
cache_manager.clear_cache()

# 只清理30天前的缓存
cache_manager.clear_cache(older_than_days=30)
```

### 自定义缓存键

高级用户可以通过自定义缓存键来优化特定场景的缓存效率：

```python
cache_key = cache_manager._get_cache_key(
    'custom_data',
    **custom_params
)
```

## 常见问题解答

**Q: 缓存系统会占用多少磁盘空间？**  
A: 根据缓存的数据量而定，通常在几百MB到几GB之间。系统会记录磁盘使用量，可通过`get_stats()`查看。

**Q: 如何确认缓存系统正常工作？**  
A: 查看性能报告中的命中率，正常工作时会显示较高的命中率(通常>80%)和API调用次数显著减少。

**Q: 缓存数据会过期吗？**  
A: 缓存数据不会自动过期，但可以通过`clear_cache`方法手动清理过期数据。

**Q: 预加载会占用多少时间？**  
A: 首次预加载需要从API获取数据，可能需要几分钟至几十分钟，具体取决于数据量。后续使用同样数据的回测将显著加快。

## 性能参考

在典型的回测场景中，使用数据缓存系统可以实现以下性能提升：

- 首次回测后，相同参数的回测速度提升5-20倍
- 大规模回测(500+股票，1年+数据)内存使用减少40-60%
- API调用次数减少85-95%
