# 板块特征生成与使用说明

## 1. 板块特征生成的整体逻辑

板块特征生成是量化交易系统中的重要环节，主要流程如下：

1. **数据获取**: 从数据源获取股票价格、成交量等基础数据
2. **特征计算**: 根据板块内股票数据计算板块整体特征，如平均价格、成交量、涨跌幅等
3. **特征存储**: 将生成的特征保存为Parquet或CSV格式文件
4. **特征合并**: 将各个日期的特征文件合并为主特征文件，提高访问效率
5. **特征更新**: 支持增量更新，只处理新增日期的数据

整个处理过程支持多进程并行计算，可以大幅提高特征生成效率。

## 2. 相关代码文件

### 核心文件

- **generate_sector_features.py**: 板块特征生成的主脚本，包含特征生成、存储和合并的核心逻辑
- **sector_loader.py**: 提供板块特征加载功能，供其他模块使用
- **feature_compress.py**: 提供特征文件的压缩、存储和加载功能
- **feature_generator.py**: 实现基础特征计算逻辑
- **enhanced_feature_generator.py**: 实现高级特征计算逻辑，包括涨跌停特征和排名特征
- **stock_daily_rankings.py**: 计算和管理股票日排名数据，包括十日涨幅、日涨幅、日跌幅和成交额排名

### 辅助文件

- **stock_sectors_mapping.py**: 提供股票与板块的映射关系
- **train_models.py**: 使用板块特征训练模型的脚本

## 3. 关键函数作用

### generate_sector_features.py

- **SectorFeatureManager类**: 板块特征管理器，是特征生成的核心类
  - `process_sector(sector, start_date, end_date, ...)`: 处理单个板块的特征生成
  - `merge_features(sector, output_format)`: 合并板块特征文件
  - `process_date_range(start_date, end_date, ...)`: 处理日期范围内的板块特征
  - `save_features(df, sector, date)`: 保存特征到文件
  - `generate_features(sectors, start_date, end_date, ...)`: 生成板块特征的高层接口

### enhanced_feature_generator.py

- **EnhancedSectorFeatureGenerator类**: 增强版特征生成器，提供更多高级特征
  - `_load_sector_rankings(date)`: 从stock_daily_rankings加载排名数据
  - `_calculate_limit_features(sector, stocks, date)`: 计算涨跌停相关特征
  - `_calculate_ranking_features(sector, stocks, date)`: 计算排名相关特征
  - `generate_sector_features_for_date(sector, date, preloaded_data)`: 生成特定日期的所有增强特征

### stock_daily_rankings.py

- `get_ten_day_rise_ranking(date, top_n=None, as_dataframe=True)`: 获取十日涨幅排名
- `get_daily_rise_ranking(date, top_n=None, as_dataframe=True)`: 获取日涨幅排名
- `get_daily_fall_ranking(date, top_n=None, as_dataframe=True)`: 获取日跌幅排名
- `get_daily_amount_ranking(date, top_n=None, as_dataframe=True)`: 获取成交额排名
- `get_all_rankings_for_date(date, top_n=None, as_dataframe=True)`: 获取所有排名类型数据

### sector_loader.py

- `load_sector_features(sector_name, data_dir, start_date, end_date)`: 加载板块特征数据
- `load_sector_features_for_date(sector_name, date, data_dir)`: 加载指定日期的板块特征
- `get_available_sectors(data_dir)`: 获取所有可用板块列表

### feature_compress.py

- `save_features(df, file_path, format, compress, optimize)`: 保存特征数据到文件
- `load_features(file_path, format)`: 从文件加载特征数据

## 4. 运行参数说明

`generate_sector_features.py`脚本支持多种命令行参数，用于控制特征生成的行为：

```
python generate_sector_features.py [参数]
```

### 主要参数

- `--start_date`: 开始日期，格式为YYYYMMDD
- `--end_date`: 结束日期，格式为YYYYMMDD
- `--sectors`: 要处理的板块列表，默认为所有板块
- `--force`: 是否强制重新生成特征，即使已存在
- `--batch_size`: 每批处理的日期数量
- `--max_workers`: 最大工作进程数
- `--output_format`: 输出格式，可选值为'parquet'或'csv'，默认为'parquet'

### 参数使用示例

```bash
# 生成2023年1月至6月的所有板块特征
python generate_sector_features.py --start_date 20230101 --end_date 20230630

# 强制重新生成特定板块的特征
python to/generate_sector_features.py --start_date 20230101 --end_date 20230330 --sector TGN人工智能 --force

# 使用8个工作进程，每批处理50个日期
python generate_sector_features.py --start_date 20230101 --end_date 20230630 --max_workers 8 --batch_size 50
```

### --force参数说明

`--force`参数用于控制是否强制重新生成特征：

- 不使用`--force`（默认）：程序会自动检查每个日期是否已经生成特征，只处理尚未生成的日期
- 使用`--force`：无论是否已存在特征数据，都会重新生成所有指定日期的特征

在以下情况应考虑使用`--force`参数：
- 特征计算逻辑发生变化，需要更新所有特征
- 特征数据存在错误，需要重新计算
- 确定要覆盖现有特征数据

在增量更新或程序中断后继续处理时，一般不需要使用`--force`参数。

## 5. 特征文件存储结构

生成的特征文件存储在以下目录结构中：

```
/to/local_data/sector_features/
├── TGN人工智能/
│   ├── TGN人工智能.parquet              # 原始合并特征文件
│   ├── TGN人工智能_features.parquet     # 优化后的主特征文件
│   ├── TGN人工智能_latest.csv           # 最新日期的CSV格式特征
│   └── TGN人工智能_20230101.parquet     # 单日期特征文件（可能存在）
├── TGN5G/
│   ├── ...
└── ...
```

每个板块目录包含以下文件：
- `{sector}.parquet`: 原始合并特征文件
- `{sector}_features.parquet`: 经过优化的主特征文件，是数据访问的主要入口
- `{sector}_latest.csv`: 最新日期的CSV格式特征，方便直接查看
- `{sector}_{date}.parquet`: 单日期特征文件，通常在合并后会被删除，但如果合并过程中断可能会保留

## 6. 在其他Python文件中获取板块特征

### 使用sector_loader.py

最简单的方式是使用`sector_loader.py`中提供的函数：

```python
from sector_loader import load_sector_features, load_sector_features_for_date, get_available_sectors

# 获取可用板块列表
sectors = get_available_sectors()
print(f"可用板块: {sectors}")

# 加载特定板块的特征数据
df = load_sector_features("TGN人工智能", start_date="20230101", end_date="20230630")
print(f"加载了 {len(df)} 行数据")

# 加载特定日期的板块特征
features = load_sector_features_for_date("TGN人工智能", date="20230315")
print(features)
```

### 使用stock_daily_rankings.py获取排名数据

要获取股票排名数据，可以使用`stock_daily_rankings.py`中的函数：

```python
from stock_daily_rankings import get_all_rankings_for_date, get_ten_day_rise_ranking

# 获取特定日期的所有排名数据
rankings = get_all_rankings_for_date('20250317')

# 获取特定日期的十日涨幅排名
ten_day_rankings = get_ten_day_rise_ranking('20250317')
```

### 在train_models.py中使用板块特征

`train_models.py`中已经包含了加载和使用板块特征的逻辑：

```python
# 使用_load_sector_features函数加载板块特征
sector_features = _load_sector_features(start_date, end_date)

# 或者使用train_with_sector_features函数直接训练模型
train_with_sector_features(sector_name, date, model_dir, lookback_days=30, forward_days=5)
```

### 直接使用pandas读取

如果需要直接访问特征文件，也可以使用pandas直接读取：

```python

# 读取主特征文件
```

## 7. 增强特征说明

### 7.1 排名类特征

通过`EnhancedSectorFeatureGenerator`类计算的排名特征包括：

- **十日涨幅排名特征**
  - `ten_day_rise_count`: 板块内股票在十日涨幅榜的数量
  - `ten_day_rise_ratio`: 板块内股票在十日涨幅榜的占比
  - `ten_day_rise_weighted`: 十日涨幅榜的加权得分（排名越靠前权重越大）

- **当日涨幅排名特征**
  - `daily_rise_count`: 板块内股票在日涨幅榜的数量
  - `daily_rise_ratio`: 板块内股票在日涨幅榜的占比

- **当日跌幅排名特征**
  - `daily_fall_count`: 板块内股票在日跌幅榜的数量
  - `daily_fall_ratio`: 板块内股票在日跌幅榜的占比

- **成交额排名特征**
  - `daily_amount_count`: 板块内股票在成交额榜的数量
  - `daily_amount_ratio`: 板块内股票在成交额榜的占比

这些特征有助于判断板块在市场中的热度和强弱，是板块轮动策略的重要指标。

### 7.2 涨跌停特征

`EnhancedSectorFeatureGenerator`同时也计算了涨跌停相关特征：

- `limit_up_ratio`: 板块中涨停股票的比例
- `limit_down_ratio`: 板块中跌停股票的比例
- `near_limit_up_ratio`: 板块中接近涨停(涨幅>7%)股票的比例
- `limit_open_ratio`: 板块中一字板开盘涨停股票的比例

这些特征反映了板块的市场情绪和强度，对判断板块未来走势有重要参考价值。

## 8. 注意事项与最佳实践

1. **板块特征存储效率**：
   - Parquet格式比CSV更节省存储空间且读取更快
   - 优先使用`{sector}_features.parquet`文件获取特征数据

2. **增量更新**：
   - 普通更新无需使用`--force`参数，系统自动识别新增日期
   - 分批生成特征时，不同日期区间可分开处理，无需担心重复计算

3. **特征合并**：
   - 合并过程可能会删除单日期特征文件，这是正常行为
   - 如果发现大量单日期文件存在，可能是之前的合并过程被中断，可以手动执行合并

4. **多进程优化**：
   - 设置合理的`--max_workers`参数可提高处理效率
   - 推荐值为CPU核心数或略少于核心数

5. **内存管理**：
   - 处理大量数据时，适当调小`--batch_size`可减少内存占用
   - 默认的批处理大小为30个交易日

6. **排名数据集成**：
   - 确保`stock_daily_rankings.py`中的排名数据已经更新到所需日期
   - 排名特征依赖于`get_all_rankings_for_date`函数返回的数据
